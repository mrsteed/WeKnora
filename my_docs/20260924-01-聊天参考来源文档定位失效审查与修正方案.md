# 聊天「参考来源」文档定位失效：前后端审查与修正方案

- 日期：2026-09-24
- 工程：WeKnora（平台端 `/platform/chat/:id` → `/platform/knowledge-bases/:kbId?knowledge_id=xxx`）
- 现象入口：
  - 聊天页：`/platform/chat/caa752eb-06a2-4b82-b39a-458fc66fe94e`（右侧「参考来源 · 26」抽屉）
  - 参考文档链接：`/platform/knowledge-bases/1e5560e2-0a9c-415c-94df-c38a25c2c206?knowledge_id=2e399999-6c05-4f47-ac12-66ff6b8f0359`
  - 目标文档：`附件4：防火监督、法制与火调技术岗位大练兵学习大纲.doc`
- 结论一句话：**目标文档在知识库的子目录里，而知识库页面收到 `knowledge_id` 后只在「根目录」这一层的列表里找它，找不到，于是既不滚动、不高亮、（最终）也不弹出详情抽屉——用户看到的就是"列表空的（知识为空，拖放上传），没有任何定位"。**

---

## 1. 一句话结论（TL;DR）

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| P1（根因） | 文档列表接口默认只查**根目录一层**，定位逻辑不感知目标文档的 `folder_path` | `KnowledgeBase.vue` `tryAutoOpenDocument` + 列表请求参数 `filterParams` | 目标文档在子目录 → `cardList.find` 永远为 `undefined` → 定位流程静默失败 |
| P2 | 全链路**没有任何滚动/高亮**逻辑（无 `scrollIntoView`、无 highlight 状态） | `KnowledgeBase.vue` | 即使文档在第 1 页根目录，也只是"打开了页"，列表停在顶部，用户仍然看不出定位到了哪条 |
| P3 | 找不到时的兜底是 `openCardDetails({ id })` 打开**空壳详情抽屉**；且该分支的触发条件依赖 `cardList.length > 0`，本例（根目录 0 条）连兜底都不会执行 | `KnowledgeBase.vue` L1232 附近 + `cardList` watcher L1294 | 表现为"什么都没发生" |
| P4（次要） | 列表分页懒加载（`pageSize>=35`，滚动加页）；若目标文档在根目录但超过第一页，同样找不到 | `KnowledgeBase.vue` `handleScroll` | 大库定位不稳定 |
| P5（体验） | 参考来源链接 `target="_blank"` 新标签冷启动，与 P1/P2 叠加使体验完全断裂 | `docInfo.vue` / `ChatReferencesDrawer.vue` | 新开的页一片"知识为空" |

实测证据（2026-09-24，浏览器 + 直连 API，登录态 hlsa@hlsa.com）：

1. 列表接口 `GET /api/v1/knowledge-bases/1e5560e2-.../knowledge?page=1&page_size=35&folder_path=`（空 folder_path = 浏览根目录一层）→ **`total: 0`**。页面因此渲染"知识为空，拖放上传"。
2. 目标文档实际位置：`folder_path = 3.AI+业务培训与考核/关于举行2023年度第二次防火监督、法制和火调技术岗位大练兵比武考核的通知/附件`（目录树 19 个文档全在子目录里）。
3. `GET /api/v1/knowledge/2e399999-...` → 200，返回完整 `file_name`、`folder_path`、摘要（**说明后端单文档接口完全可用，前端没利用**）。
4. `GET /api/v1/chunks/2e399999-...?page=1&page_size=5` → 200，`total: 7`（分块数据完好，内容能渲染）。
5. 用 `keyword=附件4：防火监督` 查列表 → `total: 1`，**能搜到**且返回 `folder_path`（说明"搜索定位"是后端现成能力）。
6. 页面 DOM 检查：`.doc-main-drawer` 处于 `visibility:hidden`、位移出屏（t-drawer 常驻 DOM 的假可见），即**详情抽屉实际从未展示给用户**；文档区卡片数 = 0。

## 3. 根因链（按发生时序）

```
用户点击参考来源"查看文档详情"（target=_blank 新标签冷启动）
  → 新标签打开 /platform/knowledge-bases/:kbId?knowledge_id=:kid
  → onMounted: loadKnowledgeFiles 以「根目录一层、page=1」请求列表
  → 列表返回 total=0（19 个文档全在子目录）
  → cardList watcher: newValue.length=0 → 不满足 pendingKnowledgeId && length 条件
  → tryAutoOpenDocument 从未执行 → 无滚动、无高亮、无抽屉
  → 用户看到：左侧目录树有内容、中间列表"知识为空，拖放上传"，无任何定位
```

即使文档**在根目录第一页**，现状也只是弹一个详情抽屉，列表本身不滚动不高亮——"定位"的语义（在列表里看见那条、知道是哪条）完全不成立。目标文档**在子目录**（本例）或**在根目录第 2 页以后**（大库）时则彻底失败连兜底都没有。

---

## 4. 修正方案

总体思路：把"定位"从「依赖列表恰好包含该卡片」改成「**先单查目标文档拿到 `folder_path`，把列表导航切到目标所在目录/搜索态，等目标卡片出现在 DOM 后滚动 + 高亮，再打开详情抽屉**"。所有修改都在前端，后端零改动（下载端点、权限、folder_path 字段全已具备）。

### 4.1 改动一（核心）：重写 `tryAutoOpenDocument` 定位流程

文件：`frontend/src/views/knowledge/KnowledgeBase.vue`（L1227-1244 附近）

```ts
import { getKnowledgeDetails } from '@/api/knowledge-base/index';  // 顶部已 import 可复用现成的

const locatingKnowledgeId = ref<string | null>(null);   // 新增：当前定位目标（驱动高亮）
let locateTimer: number | null = null;

const tryAutoOpenDocument = async () => {
  const targetId = pendingKnowledgeId.value;
  if (!targetId) return;
  pendingKnowledgeId.value = null;

  // ① 先单查目标文档（本例实测 200，且返回 folder_path / file_name / type / source）
  let meta: any = null;
  try {
    const r: any = await getKnowledgeDetails(targetId);
    if (r?.success && r.data) meta = r.data;
  } catch { /* 删除/无权限时走兜底 */ }

  // ② 找到就直接定位；找不到再切到目标所在目录（或全库搜索态）把卡片拉进列表
  const locateInLoaded = (): boolean =>
    !!cardList.value?.find((c: KnowledgeCard) => c.id === targetId);

  if (locateInLoaded()) { scrollToAndHighlight(targetId); return; }

  if (meta?.folder_path) {
    // 导航进目标所在目录（目录树接口已支持），让目标卡片进入第一层列表
    selectedFolderPath.value = meta.folder_path;
    await loadKnowledgeFiles(kbId.value);
    if (locateInLoaded()) { scrollToAndHighlight(targetId); return; }
  }

  // 兜底：用精确文件名做全库搜索（folder_recursive=true），keyword 接口实测可命中
  if (meta?.file_name || meta?.title) {
    docSearchKeyword.value = meta.file_name || meta.title;
    await loadKnowledgeFiles(kbId.value);   // watch(docSearchKeyword) 已会重置分页并加载
  }

  // ③ 卡片出现后：滚动 + 高亮 + 开抽屉（带重试，覆盖懒加载/异步渲染）
  const found = await waitForCard(targetId, 8, 300);
  if (found) {
    scrollToAndHighlight(targetId);
    nextTick(() => openCardDetails(cardList.value.find((c: KnowledgeCard) => c.id === targetId)!));
  } else {
    // ④ 彻底找不到（跨租户/已删除）：直接用 meta 开"空壳详情"，抽屉内仍有下载/摘要
    nextTick(() => openCardDetails({ id: targetId } as KnowledgeCard));
  }
};

const waitForCard = (id: string, tries: number, delay: number): Promise<boolean> =>
  new Promise((resolve) => {
    let n = 0;
    const tick = () => {
      if (cardList.value?.find((c: KnowledgeCard) => c.id === id)) return resolve(true);
      if (++n >= tries) return resolve(false);
      locateTimer = window.setTimeout(tick, delay);
    };
    tick();
  });
```

要点：
- `pendingKnowledgeId` **不再作为"必须清空"的门控**挂在 `cardList.length > 0` 上（这是 P3 的直接病根）；改为本函数自行完成"查→导航→等待→定位"。
- 目录导航用现成的 `selectedFolderPath`（其 watcher 会自动 `resetPage + loadKnowledgeFiles`，此处显式 await 一次保证时序）；搜索用现成的 `docSearchKeyword`。
- 定位完成后建议 4 秒后清除高亮并**还原**临时设置的目录/搜索词（把 `selectedFolderPath` 复位到进入前的值、清空 `docSearchKeyword`），让列表回到用户预期的浏览态——这是体验加分项，不做也不会错。

### 4.2 改动二：滚动 + 高亮（补齐从未写过的 P2 逻辑）

文件：`frontend/src/views/knowledge/KnowledgeBase.vue`

```ts
const scrollToAndHighlight = (id: string) => {
  locatingKnowledgeId.value = id;
  const tick = () => {
    const el: HTMLElement | null =
      document.querySelector(`.knowledge-card[data-select-id="${id}"]`) ||
      document.querySelector(`.doc-list-row[data-select-id="${id}"]`);
    if (el) {
      el.scrollIntoView({ behavior: 'smooth', block: 'center' });
      el.classList.add('knowledge-locate-highlight');
      window.setTimeout(() => {
        el.classList.remove('knowledge-locate-highlight');
        if (locatingKnowledgeId.value === id) locatingKnowledgeId.value = null;
      }, 3000);
      return;
    }
    requestAnimationFrame(tick);       // 卡片还在渲染中
  };
  requestAnimationFrame(tick);
};
```

注意：`data-select-id` 在 grid（`DocumentCardView.vue` L352）和 list（`DocumentListView.vue` L335）两种视图都存在，选择器两种都命中；`scrollIntoView` 作用在 `.doc-scroll-container`（`ref="knowledgeScroll"`）内即可自动滚动该容器，不会误滚页面。

高亮样式（`KnowledgeBase.vue` `<style>`，作用于子组件需非 scoped 或 deep）：

```less
@keyframes kb-locate-pulse {
  0%, 100% { box-shadow: 0 0 0 0 transparent; }
```

### 4.3 改动三：参考来源卡片加"下载"与"原文外链"（用户诉求 ②）

**a) 聊天侧 `ChatReferencesDrawer.vue` / `docInfo.vue` 的 reference 项**

在"查看文档详情"跳转图标旁再放一个"下载"图标（`t-icon name="download"`），点击时：

```ts
import { downKnowledgeDetails } from '@/api/knowledge-base/index';   // 已存在的 API 函数
import { resolveKnowledgeDownloadFileName } from '@/views/knowledge/knowledgeDownloadFileName';

async function downloadReference(item: ReferenceListItem) {
  try {
    const blob = await downKnowledgeDetails(item.knowledgeId!);
    const url = URL.createObjectURL(blob);
    const a = document.createElement('a');
    a.href = url;
    a.download = resolveKnowledgeDownloadFileName({
      file_name: item.title, title: item.title,

    document.body.appendChild(a); a.click();
    nextTick(() => { a.remove(); URL.revokeObjectURL(url); });
  } catch {
    MessagePlugin.warning(t('chat.referenceDownloadDenied') /* 新增文案：无下载权限 */);
  }
}
```

抽屉头部已有下载按钮（L1561-1565，`downloadFile` L1510），**保留即可**——改动一的空壳兜底（4.1④）打开的抽屉同样带它。需要补的是**"定位到原文位置"按钮**：

### 4.4 改动四（可选增强）：同标签打开代替新标签

参考来源跳转 `target="_blank"`（`docInfo.vue` L30、`ChatReferencesDrawer.vue` L77）是新体验断裂的放大器：新标签冷启动时用户看不到原对话上下文，且列表"知识为空"更显得像"出错了"。建议改为：

- 默认**同标签** `router.push`（保留浏览器返回键回到对话）；
- 右键/Shift 点击仍走 `<a href>` 新标签（保留 `<a>` 与 `:href` 只把 `target` 移除并在 `@click.prevent` 里 `router.push(getDocumentHref...)`）。

若产品上坚持新标签，则改动一必须保证冷启动路径体验自洽（本方案已保证：单查详情 → 导航目录 → 滚动高亮 → 自动弹抽屉）。

### 4.5 明确不做 / 后端无需改动的部分

1. 后端 `ListKnowledge` 不建议为定位加 `id=` 过滤参数——前端"先单查详情拿 folder_path 再目录导航/搜索"即可覆盖，且 keyword 全库搜索为现成能力（已实测命中）。加参数要动 API 契约 + scoped API key 能力矩阵，收益低。
2. 下载权限矩阵（`/knowledge/:id/download` 需 Contributor + KB 写权限，`routes_knowledge.go` L118）不动：前端按 4.3 的 403 降级处理即可（按钮点击后 warning；KB 页内已有 `canDownloadKnowledge` computed 可直接前置隐藏按钮）。
3. `chunk_id` 级定位（跳到抽屉内具体 chunk 并展开该 chunk）为二期：聊天引用其实带 `chunk_id`（`knowledge_references[].id` 即 chunk id），可进一步 `?knowledge_id=xxx&chunk_id=xxx`，抽屉 `getfDetails` 加载后滚动到对应序号 chunk。本期先做到"文档级"。

### 4.8 风险与回归面

- **时序**：`selectedFolderPath` 的 watcher 与显式 `await loadKnowledgeFiles` 会各触发一次列表请求 → 重复请求一次，可接受；若想省掉，可在 4.1 中手动设置后 `nextTick` 内直接 await 一次加载并临时 flag 抑制 watcher（注意与 `resetPage` 的页面计数一致）。
- **搜索词污染**：4.1 兜底搜索会把 `docSearchKeyword` 设为文件名；4.1 的"复位"步骤必须清空它，否则用户随后手动搜索会先看到被污染的结果。
- **`openCardDetails` 空壳抽屉**（保留现有 L241 else 分支语义）：`getCardDetails({id})` 内部 `getKnowledgeDetails` catch 静默（`useKnowledgeBase.ts` L211 `.catch(() => {})`），建议在 T4 场景显式提示，避免"空抽屉无解释"。
- **marquee 选中态**：`scrollIntoView` 不会触发 `@mousedown`，与批量选择框选无冲突。
- **列表视图切换**：grid/list 两视图选择器均已覆盖（4.2 注释）；FAQ 型 KB（`isFAQ`）本就不走 `?knowledge_id` 路径，无影响。
