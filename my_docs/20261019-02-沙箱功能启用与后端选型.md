# 沙箱功能启用与后端选型（WeKnora）

> 生成日期：2026-10-19
> 依据文档：WeKnora 官方《技能目录与沙箱》（website-docs/03-features/22-skills-sandbox.md）、
> 《沙箱部署与排障》（website-docs/06-development/04-sandbox-deployment.md），并对照本机
> WeKnora-sync_v0.8.3_base 仓库的 .env、system_settings 落库值与内部源码逐项核实。

---

## 1. 当前系统情况盘点

当前为 **dev 模式**：后端 `go run` 跑在宿主机，postgres/redis/minio/docreader 为 `-dev` 命名容器。

| 项 | 现状 | 对沙箱的影响 |
|----|------|-------------|
| 运行模式 | dev：后端宿主机 `go run`，基础设施容器化 | app 直接跑在宿主 → 可直接用本机 Docker daemon，**无需挂 socket 进 app 容器**（那是生产容器化部署才需要的） |
| Docker daemon | 本机 Docker 正常（大量 `-dev` 容器在跑） | 满足 Docker 后端前提 |
| `WEKNORA_SANDBOX_DOCKER_ENABLED` | `.env` 已 = `true` | 环境层已开 |
| DB 落库值 | `system_settings` 表**无** `sandbox.docker_enabled` 行 | 三层解析 DB > env > false，DB 无行 → env 的 true 生效，无需额外操作 |
| 沙箱镜像 | 本地只有 `wechatopenai/weknora-sandbox:latest`(346MB) | 代码默认镜像是 `:main`（`internal/sandbox/sandbox.go` DefaultDockerImage）→ **需补 main 镜像** |
| `MAX_SKILL_BUNDLE_SIZE_MB` | `.env` 已设 256 | 技能包上传上限就绪 |
| E2B / CubeSandbox 集群 | 均无自托管集群 | 两条路都不可用 |
| Lite `host` 本机沙箱 | 仅 macOS 桌面版，Linux 不支持 | 不可用 |
| Redis / 多副本 | 单实例 | 内存态即可，无需额外配置 |

### 沙箱后端开关的三层解析（源码核实）

`internal/sandbox/docker_enabled.go`：
- 环境变量 `WEKNORA_SANDBOX_DOCKER_ENABLED` 是进程级回退；
- 系统设置键 `sandbox.docker_enabled`（「系统设置 → 网络安全」）落库后**覆盖 env**；
- 都未设置时默认 false；
- 未启用时保存/探测/解析 Docker 沙箱配置都会返回 `ErrDockerBackendDisabled`。

本机 DB 无落库行，故 `.env` 的 `true` 生效。

## 2. 选型结论：只有 Docker 一条路

| 后端 | 需要填写 | 本机可用性 |
|------|---------|-----------|
| Docker | 镜像；可选 daemon 地址、TLS 证书目录、CPU/内存/PID 限制、网络模式、runtime、空闲 TTL | ✅ 可用，一个会话一个长驻容器，直连本机 daemon |
| CubeSandbox | 控制面地址、数据面代理、沙箱域名、模板、API Key | ❌ 需自建 Cube 集群（含 envd 的 -cube 模板），无此基础设施 |
| E2B | API Key、模板；自托管时补 API 地址/沙箱域名/数据面代理 | ❌ 需 E2B Cloud 或自托管 E2B 兼容控制面，无 |
| host（Lite 本机沙箱） | 不用填写 | ❌ 仅 macOS 桌面版（Seatbelt），Linux 明确不支持 |

**结论**：E2B / Cube 需自建或采购一整套远端沙箱控制面+数据面网关，成本远超收益且当前无集群；
`host` 与平台不符。单实例 dev 部署下 **Docker 后端配置最少、隔离够用（容器级）、与现环境完全匹配**。

旧 `local`（宿主机裸跑、无隔离）后端已被官方移除，不可选。

## 3. 启用清单（按顺序执行）

### 3.1 补 `:main` 沙箱镜像（当前唯一硬性缺口）

```bash
cd "$HOME/workspace/WeKnora-sync_v0.8.3_base"
docker build -f docker/Dockerfile.sandbox --target sandbox -t wechatopenai/weknora-sandbox:main .
```

注意：
- 官方文档同款命令（《沙箱部署与排障》「开发验证」一节）。
- 基础镜像 `python:3.12-slim` / `node:20-slim` / `ghcr.io/astral-sh/uv:0.12.4`，直连受限时
  可走国内镜像源拉取后 retag 再构建。
- 代码注释警告：`:latest` 标签缺少 /workspace 与 input/output 目录的修复，
  `DefaultDockerImage` 在修复发版前固定指 `:main`。不建议用
  `docker tag latest main` 长期顶替（可临时跑通验证）。

### 3.2 开关已就绪，无需改配置

- `.env` 的 `WEKNORA_SANDBOX_DOCKER_ENABLED=true` 已生效。
- 注意：若之后在「系统设置 → 网络安全」页动过该开关，DB 落库值会覆盖 env，保持为「启用」。

### 3.3 UI 侧操作（配置文件管不到、必须点出来的部分）

1. 「设置 → 沙箱配置」新建 **Docker** 配置：
   - 镜像：`wechatopenai/weknora-sandbox:main`
   - daemon 地址**留空**（app 跑在宿主机，自动检测 DOCKER_HOST / 当前 Docker context）
   - 网络模式：`bridge`（仅接受 bridge / none；bridge 可出网供安装依赖，`none` 则需另行放行软件源）
   - CPU/内存/PID 默认 2 核 / 2 GiB / 512 即可
   - 运行「**完整验证**」：会真实创建沙箱、执行探针并清理，确认链路通
2. 「工具箱 → 技能管理」添加技能（ZIP / `@owner/slug` / GitHub URL 等），安装到该沙箱。
   - 目录收录成功 ≠ 可用；安装状态就绪后才能执行。
   - 安装走内置安装智能体（读 SKILL.md、装依赖、校验前提命令），失败会给出原因。
3. 智能体编辑器「技能」分区：选择沙箱 + 技能范围（全部 / 指定 / 禁用）。
4. 对话中 `@技能` 或自然语言触发；附件进 `/workspace/input`，产物在 `/workspace/output`，
   对话右侧「沙箱可视化」面板「产物」标签下载。

## 4. 运维注意事项

| 项 | 说明 |
|----|------|
| 技能快照磁盘 | 安装通过 `docker commit` 生成 `weknora-skill/` 本地镜像；增量快照继承旧层，删旧 tag 不一定释放磁盘；卸载技能只加删除标记层。需监控 `/data/docker` 磁盘，清理前确认会话与快照引用 |
| 交互终端 | 走 WebSocket（`POST .../sandbox/terminal-ticket` 换短期票据）。入口代理需对该路径转发 WS Upgrade、放宽读超时。不玩终端可忽略 |
| 默认执行账号 | 沙箱内 `root`，`/workspace` 只是约定目录、不是权限边界 |
| 空闲回收 | Docker 空闲 TTL 默认 1800 秒；终端打开期间刷新活跃标记不会被回收 |
| 多副本 | 若未来 app 多副本，必须共享 Redis（保存 session→sandbox 绑定与桌面状态）；当前单实例无需 |
| 桌面能力 | Docker 后端不支持图形桌面（仅 Cube/E2B 桌面模板） |
| 升级策略 | `skill_rollout` 默认 `next_turn`：已有会话下一轮重建沙箱，旧实例临时状态丢失，交付文件必须写 `/workspace/output` |
