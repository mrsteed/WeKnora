## 3. 主要问题

### 3.1 P0：org 可见知识库被直接放宽成“同租户全员可读”，与权限总览文档正面冲突

问题位置：

1. internal/application/repository/knowledgebase.go 第 241 行
2. internal/application/service/kb_visibility.go 第 115 行

当前代码行为：

1. ListAccessibleKBs 不再使用 orgIDs 过滤 organization_id，而是把 visibility = org 直接纳入同租户可读集合。
2. CanAccessKB 对 org 可见知识库直接返回 true，不再经过组织树作用域判断。

这与权限总览文档中的当前系统定义冲突：

1. my_docs/20260714-01-当前系统权限总览说明.md 明确写的是“org 资源命中组织树读范围可读”。
2. my_docs/20260714-02-组织人员管理与本空间知识库问题审查报告也把“当前后端已放宽”为问题现状，而不是目标收口结果。

直接影响：

1. 任意同租户成员都可以读取挂在其他组织节点上的 org 知识库。
2. 这会把“组织作用域资源”退化成“租户内公开资源”，属于权限放大。

结论：

这不是文档所描述的当前权限模型实现，而是一个扩大读取范围的行为变更。若没有同步冻结产品语义并更新文档，这一改动应判定为错误或至少不完整。

处理结论：

1. 已恢复 organization_id IN orgIDs 的读取过滤。
2. 已移除 CanAccessKB 中对 org 可见资源的直接放行。
3. 当前代码重新与权限总览文档保持一致：org 可见知识库仍按组织树读范围控制。
