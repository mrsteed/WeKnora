# 用户信息页修改密码弹框功能设计方案

> 状态：待评审（**仅先输出文档，未改任何代码**）。本文档覆盖前后端代码设计 + 复用点确认 + 拆解到子任务的开发计划，待评审通过后再进入实现阶段。

## 1. 背景与目标

`设置 → 用户信息`（路由 `Settings → userprofile`，对应文件 `frontend/src/views/settings/UserProfile.vue`）当前**只读展示**当前账号的 `ID / 用户名 / 邮箱 / 注册时间`，没有任何修改密码入口；用户必须绕出设置面板去别的入口改密，体验差。

本期目标：

1. 在 `UserProfile.vue` 页面右侧增加一个**修改密码按钮**。
2. 点击后弹出独立对话框组件，要求：
   - 输入**旧密码**。
   - 输入**新密码**。
   - 输入**确认新密码**。
   - 前端校验通过后调用后端 `POST /api/v1/auth/change-password` 完成改密。
3. 同时保证：
   - 按钮和弹框内容遵循现有 t-design 视觉规范。
   - 失败提示（弱口令、两次不一致、旧密码错误等）有对应 i18n 文案。
   - 改密成功后弹框关闭并提示成功，不需要重新登录。

## 2. 现状梳理（必须复用）

### 2.1 后端现状

后端**已经具备完整可用的本人改密接口**：

- 路由：`internal/router/router.go:570`
  `r.POST("/auth/change-password", handler.ChangePassword)`
- Handler：`internal/handler/auth.go:595 ChangePassword`
  - 接收 `{ old_password, new_password }`（`new_password` 校验 `min=6`）。
  - 读取 `h.userService.GetCurrentUser(ctx)`，再调用 `userService.ChangePassword(ctx, user.ID, req.OldPassword, req.NewPassword)`。
  - 成功返回 `{ success: true, message: "Password changed successfully" }`；失败转 `errors.NewBadRequestError`。
- Service：`internal/application/service/user.go:587 ChangePassword`
  - 通过 `bcrypt.CompareHashAndPassword` 校验旧密码。
  - 通过 `validateLoginPassword(newPassword, user.Username)` 服务端规则校验（**当前规则**：最少 6 位 + 必须含字母 + 必须含数字 + 不允许全空格 + 禁止与用户名相同）。
  - `bcrypt.GenerateFromPassword(...)` 生成新哈希并 `UpdateUser` 落库。
- API 文档：`docs/api/auth.md:294` 已经完整描述请求/响应/错误码。

接口名/路径/字段**保持不变**，本期不调整后端契约。

## 3. 设计原则

1. **零后端改动**：本期完全复用 `/auth/change-password` 接口；如需补充校验规则，沿用现有 `validateLoginPassword`。
2. **样式零自定义**：弹框骨架沿用现有 `<t-dialog>`；不引入新依赖，不重写主题 token。
3. **可复用先行**：把弹框抽成独立子组件 `ChangePasswordDialog.vue`，后续“管理员重置成员密码”也可以直接复用同一 UI（仅换接口路径与去掉旧密码字段）。
4. **错误提示友好**：先用前端校验挡住弱口令/两次不一致；旧密码错误这种只能由服务端给结论的错误，统一映射到一个通用提示文案 + 弹框保留输入。
5. **不动会话/权限**：本期不踢下线、不调整 token 生命周期；本期不增加多因素验证。

### 4.2 弹框组件 ChangePasswordDialog.vue

新文件：`frontend/src/views/settings/ChangePasswordDialog.vue`。

Props：

```ts
interface Props {
  modelValue: boolean  // t-dialog v-model:visible
}
```

Emits：

```ts
emit('update:modelValue', false)  // 关闭
emit('success')                   // 提示成功
```

内部状态：

- `oldPassword: string`（必填，密码输入框）
- `newPassword: string`（必填，最小 6 位、与用户名不同）
- `confirmPassword: string`（必填、与 newPassword 一致）
- `submitting: boolean`（按钮 loading）
- `oldPwdTouched` / `newPwdTouched` / `confirmTouched` 用于失焦后才显示错误，避免输入瞬间红框
- 错误状态：每个字段单独一个 `string | null`，用于 `<t-input status="error">` 与 `<template #tips>`

弹框布局（沿用现有 `<t-dialog>` 模板）：

```html
<t-dialog
  :visible="modelValue"
  :header="t('userProfile.changePasswordTitle')"
  :on-confirm="handleSubmit"
  :on-close="handleClose"
  :on-cancel="handleClose"
  width="480px"
  :confirm-btn="t('userProfile.changePasswordConfirm')"
  :cancel-btn="t('common.cancel')"
  :confirm-loading="submitting"
>
  <t-form :label-width="0">
    <t-form-item label="...">
      <t-input type="password" v-model="oldPassword" :placeholder="t('userProfile.oldPasswordPlaceholder')" />
    </t-form-item>
    <t-form-item label="...">
      <t-input type="password" v-model="newPassword" :placeholder="t('userProfile.newPasswordPlaceholder')" />
    </t-form-item>
    <t-form-item label="...">
      <t-input type="password" v-model="confirmPassword" :placeholder="t('userProfile.confirmPasswordPlaceholder')" />
    </t-form-item>
  </t-form>
</t-dialog>
```

校验顺序（前端先行），任意一步不通过就不发请求：

1. `oldPassword` 非空。
2. `newPassword` 长度 ≥ 6，包含字母 + 数字，不能全空格，不能和 username 相同（对照 `useAuthStore().user.username`）。
3. `newPassword === confirmPassword`。
4. 全部通过 → 调用 API。

API 对接：

```ts
const { execute } = useRequest(changePassword, { manual: true })
async function handleSubmit() {
  // 校验步骤 ...
  const res = await execute({ old_password: oldPassword.value, new_password: newPassword.value })
  if (res?.success) {
    MessagePlugin.success(t('userProfile.changePasswordSuccess'))
    emit('update:modelValue', false)
    emit('success')
    resetState()
  } else {
    MessagePlugin.error(res?.message || t('userProfile.changePasswordFailed'))
  }
}
```

侧边抽屉关闭：弹框关闭后清空密码字段，避免下次打开残留。

### 4.4 错误码→友好提示映射

后端 `changePassword` 失败时可能返回的 `message`（参考 `docs/api/auth.md:294` 与 `internal/handler/auth.go:595`）：

| 错误来源 | message 文案（来自后端 Service） | 前端兜底文案 |
| --- | --- | --- |
| 旧密码错误 | `invalid old password` | `userProfile.changePasswordOldWrong` |
| 服务端规则校验失败（弱密码、与用户名相同等） | `validateLoginPassword` 透传错误 | `userProfile.errors.weak` |
| 字段绑定/反序列化失败 | 由 `binding:"required,min=6"` 抛出 | 透传后端 message 或 `userProfile.changePasswordFailed` |

实现要点：在 `changePassword` 出错回调里用 `message?.toLowerCase().includes('old password')` 这种**最小关键字匹配**做路由，避免绑死在具体错误码上。

## 7. 不在本期范围

下列需求与本主题相邻，**不**纳入本期，避免范围蔓延：

1. 管理员在 `MemberTable.vue` 重置其他成员密码（已有独立方案 `my_docs/20260506-02-…md`，待后续迭代）。
2. 改密后强制目标用户重新登录 / token 失效；当前由后端在 `userRepo.UpdateUser` 阶段自动让 access token 维持原样到自然过期。
3. 多因素认证（OTP / 邮箱验证码）；当前用户系统未提供 2FA 链路。
4. 浅色 / 深色主题覆盖检视：因为只使用既有 `<t-dialog>` 与 `<t-input>`，主题 token 沿用已有，无需重新调色。
5. 与 Lite 桌面版的兼容：本期不会触碰 `AuthHandler.Login`/`AutoSetup`，桌面端登录不影响。
