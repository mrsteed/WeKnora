# 6. 多渠道接入

知识建好了，下一步是**把问答送到员工已经在用的地方**：IM 聊天窗口、企业官网、内部系统 API、开发工具（MCP/CLI）。本章覆盖全部对外渠道。

---

## 6.1 渠道总览

| 渠道 | 一句话说明 | 谁用 | 配置位置 |
|------|-----------|------|---------|
| **Web 端** | 浏览器直接访问 | 全体 | 无需配置 |
| **IM 机器人** | 在企业微信/飞书/钉钉等聊天窗口 @机器人提问 | 员工 | 设置 → IM 集成 |
| **网站嵌入 Widget** | 一段 `<script>` 贴进网页，访客免登录对话 | 对外访客 | 设置 → 网页嵌入 |
| **REST API** | 程序化调用问答/检索/入库 | 其他系统 | 空间设置 → API Key |
| **MCP Server** | 把企业内脑暴露成 29 个 MCP 工具，接 Claude Desktop / Copilot 等 | 开发者 | 独立部署 `mcp-server/` |
| **CLI（weknora）** | 命令行问答与知识管理 | 开发者 / 运维 | 本地安装 |
| **微信小程序** | 移动端轻量问答 | 员工 | 独立小程序 |
| **Chrome 插件** | 浏览器一键采集网页内容入库 | 知识管理员 | Chrome 商店安装 |

> 所有渠道共用同一套知识与 Agent 能力——**渠道只是入口**，答什么由绑定的 Agent 与知识库决定。

## 6.2 IM 集成（重点渠道）

### 支持的平台（10 个）

| 平台 | 接入模式 | 流式回复 | 接收用户文件 |
|------|---------|---------|------------|
| 企业微信 wecom | websocket（默认）/ webhook | websocket 模式支持 | 是 |
| 飞书 feishu | websocket（默认）/ webhook | 是（流式卡片） | 是 |
| Lark 飞书国际版 | 同飞书 | 是 | 是 |
| Slack | websocket（默认）/ webhook | 是 | 是 |
| Telegram | websocket（默认长轮询）/ webhook | 是 | 是 |
| 钉钉 dingtalk | websocket（Stream 模式）/ webhook | 是（AI 卡片） | 是 |
| Mattermost | webhook | 是 | 是 |
| 微信 wechat | 长轮询（强制） | 否（整段回复） | 是 |
| QQ 机器人 qqbot | websocket | 否 | 否 |
| 云之家 yunzhijia | webhook / websocket | 否 | 是 |

### 配置步骤

1. **平台侧创建应用/机器人**，拿到凭据（各平台后台操作，所需字段在表单中有提示）；
2. **「设置 → IM 集成」→ 新建渠道**：
   - 选平台，填凭据；
   - **绑定一个 Agent**（决定这个机器人用哪些知识库、模型、能否联网、挂哪些工具）；
   - 可选：绑定"文件知识库"——用户发给机器人的文件/图片自动入库该库，实现"边聊边沉淀"；
3. **接入模式**：
   - **websocket / 长连接 / 长轮询**（多数平台默认）：WeKnora 主动连平台网关，**无需公网回调地址**，内网部署也能用；
   - **webhook**：把回调地址 `https://<你的域名>/api/v1/im/callback/<渠道ID>` 填到平台事件订阅处，需要公网可达。
4. 点「启用」，在平台上 @机器人提问即可。

### 渠道行为配置

| 配置 | 说明 |
|------|------|
| 输出模式 | `stream`（流式逐字回复，默认）/ `full`（整段一次性回复） |
| 会话模式 | `user`（按"平台+用户+群"维持上下文，默认）/ `thread`（每个线程新会话） |
| 文件入库 | 绑定文件知识库后，用户发来的文件自动解析入库 |

### IM 里的交互能力

- **@机器人提问**：走绑定 Agent 的完整流水线（检索/推理/引用）；
- **发文件给机器人**：图片/文档被理解并纳入本轮问答（可配置是否同时入库）；
- **内置命令**：如 `/help` 查看可用命令，`/reset` 清空当前会话上下文等（各平台支持略有差异）；
- **引用回复 + 线程会话**：在话题/线程里提问，上下文按线程隔离；
- **群与单聊**：都支持，会话按群/按用户隔离。

### 多实例可靠性

多实例部署（有 Redis）时，长连接渠道通过 leader 选举保证**只有一个实例**维持连接；实例宕机后其他实例自动接管，业务无感。

> 管理员可在控制台查看 IM 渠道产生的会话（只读观察，用于排查"机器人昨天怎么答的"）；普通成员看不到他人渠道会话。

## 6.3 网站嵌入 Widget（对外客服）

**用途**：给官网、帮助中心、客户门户加一个"问文档"挂件，**访客不需要企业内脑账号**即可对话。

### 配置步骤

「设置 → 网页嵌入」→ 新建渠道：

1. **绑定 Agent**（决定访客能问什么）；
2. **域名白名单（必填）**：允许嵌入的 Origin，支持三种形式：
   - 完整 `https://www.example.com`；
   - 子域通配 `*.example.com`；
   - `*`（仅开发模式允许，**生产环境拒绝**）;
3. 外观与体验：欢迎语、主题色、标题、挂件位置（四角可选）、推荐问题开关;
4. 安全与额度：
   - **限流**：单 IP 每分钟上限（默认 30）+ 渠道每日总量上限（默认 10000）；
   - 访客侧联网搜索 / 文件上传开关（默认关）；
   - 可选 Webhook 事件回调（HTTPS，HMAC 签名）；
5. 保存后复制生成的 `<script>` 代码片段，贴进目标网页即可上线。

### 安全要点（务必配置后再上线）

- **域名白名单**防止你的渠道被挂到别的网站白嫖模型额度；
- **限流**兜底防刷；
- 渠道令牌（`em_` 前缀）可随时**轮换**（旧令牌及已签发会话立即失效）；
- 访客会话按渠道隔离，管理员可查看渠道统计与明细（只读）。

## 6.4 REST API 集成

### 接入方式

1. 「空间设置 → API Key」创建密钥；
2. 勾选**细粒度能力**（按需最小授权）：

| 能力 | 覆盖操作 |
|------|---------|
| `retrieve` | 检索、读知识库/知识/分块 |
| `chat` | 会话与问答（含 Agent 对话） |
| `ingest` | 上传文档、入库 |
| `manage_kbs` | 知识库增删改、复制 |
| `manage_models` | 模型管理 |
| `message_history` | 历史消息搜索（做数据分析集成用） |
| 限定知识库 | 用 `KnowledgeBaseIDs` 把 Key 锁死在指定库，越权直接拒绝 |

3. 请求头携带 `X-API-Key: <key>` 调用，多空间用户可加 `X-Tenant-ID` 指定空间。

### 常用端点速查

| 目的 | 端点 |
|------|------|
| 登录换 JWT | `POST /auth/login` |
| 建知识库 | `POST /knowledge-bases` |
| 上传文档 | `POST /knowledge-bases/:id/knowledge/file` |
| URL 导入 | `POST /knowledge-bases/:id/knowledge/url` |
| 快速问答（SSE） | `POST /knowledge-chat/:session_id` |
| 智能推理（SSE） | `POST /agent-chat/:session_id` |
| 仅检索（JSON） | `POST /knowledge-search` |
| 历史消息搜索 | `POST /messages/search` |
| API 集成调试台 | 空间设置内提供在线调试界面，可直接粘贴参数试跑 |

> **文件直链模式**：部署设 `RESOURCE_URL_MODE=public` 后，回答中引用的图片/文件以可公开加载的直链返回，第三方页面无需二次鉴权代理即可渲染。

详细 API（约 360 端点）见 Swagger 与官方开发者文档站。

## 6.5 MCP Server（把企业内脑变成别人的工具）

仓库 `mcp-server/` 提供独立 Python MCP Server——官方 PyPI 包 **`tencent-weknora-mcp`**，把企业内脑的知识库、混合检索、会话、Agent 问答、Wiki 等能力封装成 **29 个 MCP 工具**，供 Claude Desktop、VS Code 等外部 MCP 客户端调用。

典型用法：

- 在 Claude Desktop 里直接查公司知识库；
- 让别的 Agent 调用企业的 RAG / 文档处理能力；
- 支持 `stdio` / `SSE` / `HTTP` 三种传输；用 X-API-Key 鉴权（建议配细粒度能力）。

> 注意方向区分：**MCP 客户端**（在「设置 → MCP 服务」接外部工具给 Agent 用）见 4.3；本节是**反过来**——把企业内脑暴露出去。

## 6.6 CLI（weknora 命令行）

`weknora` CLI（Go），适合脚本化与日常运维：

| 能力 | 场景 |
|------|------|
| 问答（NDJSON 流式） | 脚本里对知识库提问、批量取答案 |
| 知识管理 | 上传文件/URL/Markdown、列举与删除 |
| `--dry-run` | 预览将执行的操作 |
| auth / profile | 多环境凭据管理 |

## 6.7 微信小程序 & Chrome 插件

**微信小程序**：轻量移动端客户端——配置 API、选择知识库、导入 URL、在微信内提问。适合员工外出场景。

**Chrome 插件**：面向知识管理员的**采集工具**——在浏览器中选中文本、图片或整个页面，一键保存到企业内脑知识库，免去复制粘贴与手动上传。

## 6.8 渠道规划建议

| 对象 | 推荐渠道组合 |
|------|-------------|
| 内部员工 | Web 端 + 1 个主力 IM（如企业微信/飞书）+ 小程序（可选） |
| 对外客户 | 网站嵌入 Widget（白名单 + 限流），绑定"客服 Agent"（限定知识库 + 固定口径提示词） |
| 内部其他系统 | API Key（细粒度能力 + 限定 KB）；若对方是 AI 应用，优先 MCP Server |
| 知识采集 | Chrome 插件 + 数据源同步，双轮驱动 |
