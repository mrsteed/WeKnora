# 3. 知识库管理

知识库是组织内容的单位：一个知识库装一批相关资料，并决定这批资料**怎么切分、用什么向量模型索引、要不要额外生成 Wiki 和知识图谱**。库里的每条内容——一个文件、一个网页 URL、一段手写 Markdown、一组 FAQ——都叫「知识」，上传后会异步解析成分块并建立索引。

**按库组织资料的三个好处**：不同资料可用不同分块与模型配置；提问时可限定只检索指定库；权限与共享也按库授予。

> 本章日常操作一览：
>
> | 想做什么 | 在哪里做 |
> |---------|---------|
> | 建库、改分块与索引开关 | 知识库编辑弹窗的「分块」「索引策略」页签 |
> | 上传文件 / 导入网页 / 手写一篇 | 文档列表页上传区，或「新建」下拉 |
> | 用文件夹整理文档 | 文档列表左侧文件夹树 |
> | 打标签（一篇可多标签） | 单篇在详情里改；多篇勾选后用批量操作栏「标签」 |
> | 检查解析结果、改错字 | 打开文档 → 分块列表 → 直接编辑分块（§3.6） |
> | 补充部门、密级等自定义字段 | 文档详情里的自定义元数据（§3.1） |
> | 看谁改过什么 | 知识库设置 → 活动（§3.8） |
> | 整库复制 / 把文档挪到别的库 | 知识库列表「复制」或文档批量操作「移动」 |

---

## 3.1 知识库类型与创建

### 三种类型

| 类型 | 用途 | 说明 |
|------|------|------|
| **文档（document）** | 装 PDF/Word/网页/音视频等文件资料 | 默认类型；可开启 Wiki、图谱等索引 |
| **FAQ** | 装"标准问 + 答案"的固定问答对 | 提问时匹配的是**问题**而不是文档片段，命中直接给准备好的答案 |
| **Wiki** | 以 Wiki 页面为主的库 | 一般不必单独建 Wiki 库——普通文档库打开 Wiki 索引开关即可获得全部 Wiki 能力 |

> 注意：库绑定的**向量存储创建后不可修改**（防止索引与存储错位），建库前请规划好。

### 创建步骤

「知识库」页 → 新建 → 填名称与类型 → 初始化向导配置模型（见 2B.2）→ 保存。

配额：每个空间有存储配额（默认 10GB），建库时系统会检查剩余配额。

## 3.2 分块配置（决定检索准确度的关键）

分块是把文档切成"检索最小单元"的过程。切太碎信息不完整，切太大主题混杂。**大多数场景用默认值即可**（512 字 / 重叠 80 字 / 自适应策略）。

| 参数 | 默认 | 何时调整 |
|------|------|---------|
| 分块大小 `chunk_size` | 512 字符 | 回答缺上下文 → 调大，或改用父子分块；命中不相关 → 调小 |
| 重叠 `chunk_overlap` | 80 字符 | 条目式资料（FAQ/参数表）设 0；长篇叙述（报告/论文）设 150–200 |
| 分块策略 `strategy` | `auto`（自适应） | `auto` 由系统按文档画像选层；也可固定 `heading`（按标题）/ `heuristic`（启发式）/ `recursive`（递归切分） |
| **父子分块** | 关 | 开启后"子块（~384 字）负责检索命中、父块（~4096 字）负责提供回答上下文"，适合长文档 |
| 分隔符 | 段落 → 换行 → 句号 | 条目式资料建议用换行分隔符 |

**预览不入库**：改配置前可用分块预览功能试切一篇文档看看效果，不满意不落库。

> ⚠️ 修改分块配置后，**已有文档需重新解析**才生效（见 §3.5 批量重新解析）。

## 3.3 索引策略（四路索引开关）

知识库编辑 →「索引策略」，可分别开关：

| 开关 | 默认 | 作用 |
|------|------|------|
| 向量检索 | 开 | 语义相似度检索（依赖向量模型） |
| 关键词检索（BM25） | 开 | 精确关键词命中，与向量混合互补 |
| Wiki 页面生成 | 关 | 生成自动 Wiki（见第 5 章）；开启后可调生成粒度（聚焦/标准/详尽）与生成模型 |
| 知识图谱 | 关 | 抽取实体与关系（需部署 Neo4j，见 5.4） |

辅助开关（同在知识库设置内）：

- **问题预生成**：为每个分块预生成 3–10 个"可能被问到的问题"，提高口语化提问的召回率；
- **图片理解（VLM）**：配置视觉模型后，图片类文档（截图、扫描件）可被理解内容并参与问答；
- **语音转写（ASR）**：配置语音识别模型后，音频文件自动转成文字入库；
- **知识图谱抽取配置**：可配置领域标签、few-shot 示例与自定义提取指令，让抽取更贴合业务。

## 3.4 文档的添加方式

| 方式 | 说明 |
|------|------|
| **本地文件上传** | 拖拽或点选；支持整目录拖入（保留文件夹结构）；上传时可打标签、调整本批解析选项 |
| **URL 导入** | 粘贴网页地址，系统抓取正文转 Markdown 入库；带 SSRF 安全防护 |
| **手动录入** | 直接写 Markdown/文本条目（适合零散知识沉淀，草稿可先存后发布） |
| **数据源同步** | 飞书/Notion/语雀/RSS 定时自动拉取（见 §3.7） |
| **IM 发文件** | 在配置了文件入库的 IM 渠道里直接发文件给机器人 |
| **API 上传** | `POST /knowledge-bases/:id/knowledge/file`（multipart），供程序化入库 |

### 支持的文件格式

| 类别 | 格式 |
|------|------|
| 文档 | PDF、Word（doc/docx）、PPT（ppt/pptx）、Excel（xls/xlsx）、EPUB |
| 文本 | txt、Markdown、CSV、JSON |
| 网页 | 在线 URL 抓取、本地 HTML / MHTML 归档 |
| 图片 | jpg、png、gif、bmp、tiff、webp（需配置视觉模型理解内容） |
| 音频 | mp3、wav、m4a、flac、ogg（需配置语音识别模型） |

### 文档详情页信息

- **解析状态机**：`等待中 → 处理中 →（收尾富化）→ 已完成`，可失败/取消/重新解析；
- **分块列表**：该文档切出的全部检索片段，可逐条查看与编辑（§3.6）；
- **摘要**：文档级 AI 摘要（可开关）；
- **标签**：可挂多个标签，提问时可 `@标签` 缩小范围；
- **自定义元数据**：最多 20 个字段（如 部门/密级/版本号/负责人），值限字符串、数字、布尔；用于内部管理，会参与摘要生成与文档上下文。

## 3.5 解析状态、重新解析与批量操作

**查看进度**：文档列表页实时显示解析状态与进度；大文件、扫描件较慢属正常。系统内置解析追踪时间线，可逐阶段（解析 → 分块 → OCR → 图片描述 → 向量化…）查看耗时与失败点。

**单篇重新解析（reparse）**：文档详情 → 重新解析，可顺带调整本批解析选项（换解析引擎、改开关）。适用场景：换了一版文档内容、调整了解析配置。

**批量操作**（文档列表勾选多篇后出现操作栏）：

| 操作 | 说明 |
|------|------|
| 批量重新解析 | 一次为多篇文档重新排队解析，可携带批次级解析配置 |
| 批量打标签 | 勾选标签批量应用（自动预选公共标签） |
| 移动到文件夹 | 重新归档到目标文件夹 |
| 移动到知识库 | 跨库迁移（不复制，原库删除） |
| 批量删除 | 连带清理分块、索引与源文件 |

**整目录拖入**：把本地文件夹直接拖进上传区，系统按原目录结构创建知识库文件夹树，并保留各文件的相对位置。

## 3.6 分块编辑与版本历史

分块是"检索的最小单元"。解析结果不理想（错字、切错、OCR 误识别）时，**不必重传文档**，直接改分块：

1. 打开文档 → 分块列表 → 点进某个分块；
2. 直接编辑文本，保存后**自动重建该分块索引**（重新向量化，检索即时生效）；
3. **版本历史**：每次保存生成一个版本快照，可逐版本对比（diff）与**一键回滚**到任意历史版本；
4. 分块上的**生成问题**（问题预生成产物）可增、删、改与重新生成——预生成的问题质量直接影响口语化提问的召回。

> 建议：解析质量稳定的库少改分块；对高频被问的核心文档，值得人工校对分块与生成问题，这是"低成本提升答案质量"最有效的手段之一。

## 3.7 数据源：外部内容自动同步

团队的知识往往长在飞书、Notion、语雀里。数据源解决**持续同步**：绑定一次账号，之后按计划自动把新增与修改同步进来，删除的文档同步下架。

> 数据源是**挂在知识库上**的（不是全局设置）：目标知识库 → 编辑设置 → 「数据源」页签 → 新建连接。

### 支持的数据源（当前 5 种）

| 数据源 | 说明 |
|--------|------|
| 飞书知识库（feishu） | 支持大型 Wiki 流式同步（断点续传）、docx 逐块下钻 |
| Lark（飞书国际版） | 与飞书同一连接器，域名不同 |
| Notion | 同步指定页面/数据库 |
| 语雀 | 同步知识库文档 |
| RSS | 订阅源定时抓取（支持自定义 feed 地址） |

### 配置与同步机制

1. 新建连接 → 选类型 → 填凭据并在线授权（**凭据以 AES-256-GCM 加密落库**，接口永不回显）；
2. 选择要同步的外部空间/目录/文档范围；
3. 设定同步周期（Cron 表达式，如每日凌晨）与模式：
   - **增量同步**（推荐）：按修改时间拉取变更，首次全量；
   - **全量同步**：每次完整拉取；
   - 可开启**删除同步**（外部删了，库内也删）；
4. 同步日志完整记录每次执行：新增/更新/删除/跳过/失败条数，失败样本给出可读原因。

**冲突策略**：同名文档更新时按策略处理（以外部为准/保留本地人工编辑等），避免覆盖你的分块修改。

> 大规模同步（如上千篇文档）走流式可恢复通道：任务超时可从最近检查点续传，而非从头重来。

## 3.8 知识库的批量管理、复制与活动审计

| 操作 | 位置 | 说明 |
|------|------|------|
| 置顶 / 取消置顶 | 知识库列表 | 把常用库固定在顶部 |
| 整库复制 | 知识库列表 → 复制 | 异步任务复制全部知识、分块与配置，可查进度；适合"按部门拆库但内容同源" |
| 库内活动审计 | 知识库设置 → 活动 | 该库下"谁在何时做了什么"（上传、删除、改配置、编辑分块、Wiki 变更等） |

删除知识库 = 级联清空其下全部知识、分块、索引、Wiki 页面、标签与源文件，**不可恢复**，请谨慎。

## 3.9 常见问题（知识库相关）

| 现象 | 处理 |
|------|------|
| 解析一直"处理中" | 查看解析追踪时间线定位卡住的阶段；大文件属正常，可看任务队列面板；失败任务可重试 |
| 扫描件没识别出文字 | 确认已配置并启用视觉模型（VLM） |
| 表格解析错位 | 知识库解析设置里为 `pdf/xlsx` 指定其他解析引擎（如 MarkItDown / OpenDataLoader / MinerU）；Excel 打开"首行作为表头" |
| 换了向量模型后搜不到老数据 | 向量模型决定索引含义，更换后需重建索引（重新解析或复制新库） |
| 上传被拒"配额不足" | 空间存储配额已满，联系管理员扩容或清理旧库 |
| 想给某几篇文档单独用不同解析引擎 | 按文件类型在知识库 `parser_engine_rules` 中配置，或单篇重新解析时临时指定 |
