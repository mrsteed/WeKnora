# 1. 产品概述

## 1.1 产品定位

**IntraMind 企业内脑，一句话：把企业里散落在各处的文档，变成一个"活的、会思考的知识大脑"。**

它不是简单的文档搜索工具，而是让企业知识具备三种能力——**能回答、能推理、能自生长**：

- **能回答**：员工用自然语言提问，系统秒级检索并给出带引用的答案，替代"翻文档、问同事"；
- **能推理**：面对复杂问题，智能体会自动拆解任务、多轮检索、调用工具、联网搜索，一步步给出结论与依据；
- **能自生长**：自动 Wiki 模式让系统从原始文档中抽取条目、生成相互链接的百科页面与知识图谱，文档更新后知识库随之更新，不再依赖人工整理。

## 1.2 解决的问题

| 企业痛点 | 企业内脑的做法 |
|---------|--------------|
| 文档格式繁杂（PDF/扫描件/表格/音视频），难以被统一利用 | 独立文档解析服务：版式分析、OCR、表格抽取、图片多模态理解（VLM）、语音转写（ASR） |
| 知识分散在飞书、Notion、语雀、网盘，手动搬运很快过期 | 数据源连接器：定时自动同步（增量/全量），删除同步下架 |
| 单一关键词搜索"找不到"，向量搜索"不可控" | 向量 + 关键词（BM25）混合检索、RRF 融合、Rerank 重排、可选知识图谱增强 |
| 模型绑定单一厂商，有被锁定顾虑 | 模型抽象层：20+ 厂商、五类模型自由组合；存储 8 种向量后端、8 种对象存储可选 |
| 知识只进不出，员工仍靠老人带新人 | 内置 Agent、MCP 工具、数据分析（对 CSV/Excel 执行 SQL）、自动 Wiki 体系化沉淀 |
| 数据安全与合规 | 全栈私有化部署；凭据 AES-256 加密落盘；空间四级 RBAC + 审计日志；邀请制准入 |

## 1.3 目标用户与读者对象

| 角色 | 关注点 | 建议章节 |
|------|--------|---------|
| **普通员工（查看者）** | 随时随地提问、拿答案 | 第 2、4 章 |
| **知识管理员（编辑者/管理员）** | 建库、传文档、接数据源、维护 FAQ 与 Wiki | 第 3、4、5 章 |
| **空间管理员（Admin/Owner）** | 管成员、配模型、接 IM 与嵌入、API 集成 | 第 6、7 章 |
| **平台管理员（System Admin）** | 全局设置、任务队列、平台 API Key、跨空间审计 | 第 7 章 §8 |
| **IT / 集成工程师** | 部署、API、MCP Server、CLI | 第 2、6、8 章 |

## 1.4 部署形态

| 形态 | 数据底座 | 适用场景 |
|------|---------|---------|
| **Docker Compose（标准）** | PostgreSQL（ParadeDB）+ Redis | 生产 / 团队自托管，**推荐** |
| **Helm** | Kubernetes（≥1.25），内置 PostgreSQL 与 Redis | 企业 K8s 环境 |
| **Lite 单二进制** | SQLite（内嵌，零外部依赖） | 个人 / 离线 / 低资源 / 演示 |

> 生产部署前请先阅读 `docker-compose.yml` 与 `.env.example` 中的环境变量说明；模型可使用本地 Ollama，也可接入任意 OpenAI 兼容的远程服务（DeepSeek、通义、智谱、OpenAI 等）。

## 1.5 一次完整的使用旅程

```
部署上线 → 注册账号（自动获得个人空间，角色为 Owner）
        → 配置模型（对话 + 向量，可加 Rerank/VLM/ASR）
        → 创建知识库（选类型：文档 / FAQ / Wiki）
        → 接入知识（上传文件 / 导入 URL / 手写 / 数据源自动同步）
        → 等待解析与索引（状态：pending → processing → finalizing → completed）
        → 提问验证（快速问答 / 智能推理，答案带引用）
        → 按需增强（Rerank、知识图谱、自动 Wiki）
        → 开放使用（邀请成员 / 接 IM 渠道 / 官网嵌入 / API 集成）
        → 持续运维（审计日志、任务队列、可观测追踪）
```

## 1.6 系统组成

整个系统由三个常驻进程 + 若干可选组件构成：

| 组件 | 职责 | 用户可见性 |
|------|------|-----------|
| **前端（Web UI）** | 浏览器操作界面：知识库、对话、设置、管理台 | 你日常操作的界面 |
| **后端 App（Go）** | 业务逻辑、检索调度、Agent 引擎、API | 接口 `http://<host>:8080/api/v1`，健康检查 `/health` |
| **文档解析（docreader, Python/gRPC）** | 把文件/URL 转成结构化文本 + 图片 | 后台自动调用，无需直接操作 |
| PostgreSQL / 向量库 | 业务数据、向量索引、全文索引 | 运维关注 |
| Redis | 任务队列、缓存、限流 | 运维关注 |
| 可选：Ollama / 远程模型 API | 提供 LLM、Embedding、Rerank、VLM、ASR | 模型配置时关注 |
| 可选：Neo4j | 知识图谱存储 | 开启图谱功能时启动 |
| 可选：Langfuse | 全链路可观测 | 管理员查看追踪 |
| 可选：SearXNG | 自托管网络搜索 | 开启联网搜索且无商业 Key 时使用 |

## 1.7 版本说明（0.7.x 近期更新摘要）

- 知识库**文件夹树**：文件夹路径独立入库，可像文件管理器一样浏览、重命名、重新归档；
- **分块编辑与版本历史**：可视化编辑检索分块、逐版本 diff 与回滚、自动重建索引、文档自定义元数据；
- **Wiki 页面版本历史**：快照 + 行级 diff + 一键回滚 + 浏览器内手动编辑；
- **API 文件直链模式**（`RESOURCE_URL_MODE=public`）：第三方应用可直接加载图片或文件；
- 飞书云盘数据源、文档批量打标签；
- 官方产品文档站（约 360 个 API 端点、约 150 个环境变量的完整说明）。

完整变更记录见仓库 `CHANGELOG.md`。
