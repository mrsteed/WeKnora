# 2. 快速上手

本章带你从零开始部署并跑通第一个"能回答自己文档内容"的知识库。全程在网页界面完成，顺利的话十几分钟，其中大部分时间花在等文档解析上。

> 分两部分：**2A 给 IT/部署同事的**（怎么把服务跑起来）、**2B 给业务使用者的**（注册后怎么用）。如果服务已由 IT 部署好，直接从 2B 开始。

---

## 2A. 部署与服务启动

### 2A.1 环境要求

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| Docker + Docker Compose | Docker 20.10+，Compose v2 | 标准部署必需 |
| 服务器资源 | 建议 4 核 CPU / 8GB 内存起步 | 文档解析服务（含 LibreOffice、Playwright）较吃内存 |
| 磁盘 | 按知识库规模预留 | PostgreSQL 数据卷 + 文件存储目录 |
| 模型 | 本地 Ollama 或任意 OpenAI 兼容远程 API | 至少需要 1 个对话模型 + 1 个向量模型 |

### 2A.2 三步启动（Docker Compose 标准部署）

```bash
# 1) 获取代码（或下载 release 包解压）
git clone https://github.com/Tencent/WeKnora.git
cd WeKnora

# 2) 准备环境配置
cp .env.example .env
# 用编辑器打开 .env，至少修改以下必填项：
#   DB_USER / DB_PASSWORD / DB_NAME   —— 数据库账号
#   REDIS_PASSWORD                    —— Redis 密码
#   JWT_SECRET                        —— 会话令牌密钥
#   SYSTEM_AES_KEY                    —— 敏感凭据加密密钥（建议 32 字节随机串）

# 3) 拉取镜像并启动
docker compose pull
docker compose up -d
```

或使用一键脚本（等价操作，额外做 Ollama 检查与沙箱镜像预拉取）：

```bash
make start-all
```

### 2A.3 验证服务状态

```bash
docker compose ps                          # 等待所有服务变为 healthy / running
curl http://localhost:8080/health          # {"status":"ok"} 即后端就绪
```

| 服务 | 默认端口 | 说明 |
|------|---------|------|
| 前端（frontend） | `80`（`FRONTEND_PORT` 可改） | 浏览器入口，`/api/` 自动反代到后端 |
| 后端（app） | `8080`（`APP_PORT` 可改） | Web UI 与 API 都在它后面 |
| 数据库 / Redis / 解析服务 | 不映射宿主端口 | 仅容器网络内通信 |

### 2A.4 指定第一个系统管理员（团队部署建议）

新部署**没有任何系统管理员**。指定方法：

1. 先正常注册一个管理账号（见 2B.1）；
2. 在 `.env`（app 服务）中设置 `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=<该账号邮箱>`；
3. `docker compose up -d` 重启，启动时会自动将该用户提升为系统管理员。

> 该变量只在"当前部署还没有系统管理员"时生效一次，可长期保留。之后新增/撤销管理员都在网页界面操作（见 7.8）。

### 2A.5 可选组件（按需启用）

```bash
# 启用知识图谱（Neo4j）
docker compose --profile neo4j up -d
# 并设置 NEO4J_ENABLE=true

# 启用自托管网络搜索（SearXNG）
docker compose --profile searxng up -d

# 启用 S3 兼容对象存储 / 向量库(Qdrant/Milvus) / Langfuse 可观测等
docker compose --profile minio up -d        # 依次类推
```

各 profile 的用途与端口见 `docker-compose.yml` 注释。

### 2A.6 版本升级

```bash
# 修改 .env 中 WEKNORA_VERSION 为目标版本（或保持 latest）
docker compose pull
docker compose up -d
```

> 数据库迁移在服务启动时自动执行（`AUTO_MIGRATE=true` 默认开启），无需手动操作。

## 2B. 第一次使用（业务用户视角）

### 2B.1 注册与登录

浏览器打开 `http://<服务器地址>`，首次访问落到登录/注册页：

1. 切换到「注册」页签，填写用户名（2–50 字符）、邮箱、密码（8–32 位，含字母与数字）；
2. 注册完成后**自动得到一个属于你的工作空间**，你在该空间的角色是 **Owner（所有者）**；
3. 用账号登录，进入主界面：左侧是知识库、会话与设置入口，右侧是问答区。

> 团队部署中，注册出第一个账号后建议**关闭公开注册**（`设置 → 系统 → 注册模式` 改为「邀请制」），之后通过邀请链接加人，见 7.3。

### 2B.2 创建知识库并配置模型（第 1 步）

模型配置是**按知识库**进行的：

1. 「知识库」页 → **新建知识库**，填写名称，选择类型：
   - **文档**（document，默认）——装 PDF、Word 等文件资料；
   - **FAQ**——装"标准问 + 答案"的固定问答对；
   - （Wiki 类型库用于纯 Wiki 场景，一般文档库直接开启 Wiki 索引开关即可，见第 5 章）
2. 在初始化向导中配置模型：
   - **对话模型（LLM，必填）**：生成回答用；
   - **向量模型（Embedding，必填）**：把文档转成向量用。**⚠️ 建库后不要再换**，否则需重建索引；
   - 其余可选：重排 Rerank（让答案更准）、图片理解 VLM、语音转写 ASR、知识图谱抽取、问题预生成——都可先不开，以后随时加；
3. 填写模型的 `Base URL` + `API Key`（本地 Ollama 填 `http://host.docker.internal:11434`），点「测试」确认连通，再保存。

> **常见坑**：后端跑在容器里时，Ollama 地址填 `http://localhost:11434` 会连不上，必须填 `http://host.docker.internal:11434`。

### 2B.3 上传文档（第 2 步）

进入刚建的知识库，把文件拖进上传区，或粘贴一个网页 URL：

1. 支持的格式：PDF、Word、PPT、Excel、TXT、Markdown、HTML、EPUB、图片、音频（mp3/wav）等 12+ 种；
2. 上传确认对话框里可顺手**打标签**、调整本批文件的解析选项；
3. **整目录拖入**会保留原始文件夹结构（文件夹树）；
4. 上传后文档异步解析，状态依次为 `等待中 → 处理中 → 收尾富化 → 已完成`；PDF 扫描件和大文件会慢一些，列表页实时刷新进度。

### 2B.4 提问（第 3 步，跑通闭环）

1. 进入对话页，在输入框上方选择刚建的知识库（也可多个）；
2. 直接提问，如"这份文档讲了什么？"；
3. 默认使用内置**快速问答**模式：检索相关片段 → 大模型作答 → 回答正文中带**引用角标**，点击可跳转到原文分块；右侧引用面板列出本轮全部来源；
4. 复杂问题可切换到**智能推理**模式（见 4.2）。

至此，最小闭环已跑通 ✅

### 2B.5 再进一步（推荐路径）

| 需求 | 操作 | 章节 |
|------|------|------|
| 答案不够准 | 开启 Rerank 重排、调整分块大小 | 3.4、7.7 |
| 让知识自动进来 | 给知识库配置飞书 / Notion / 语雀 / RSS 数据源 | 3.7 |
| 固定答案类内容（制度、报销流程） | 建 FAQ 库，批量导入问答对 | 4.5 |
| 让知识库"自己长出"百科与图谱 | 在库设置开启 Wiki 索引 | 5.1 |
| 拉同事一起用 | 空间 → 成员 → 邀请，分配角色 | 7.3 |
| 把问答放到企业微信/飞书/官网 | 配置 IM 渠道或嵌入渠道 | 第 6 章 |

## 2C. 用 API 跑通同样链路（集成工程师可选）

统一前缀 `/api/v1`。以下链路可直接复制运行（需 `curl` 与 `jq`）：

```bash
BASE=http://localhost:8080/api/v1

# 1) 注册（首次部署时）
curl -s -X POST $BASE/auth/register -H "Content-Type: application/json" \
  -d '{"username":"demo","email":"demo@example.com","password":"pass123456"}'

# 2) 登录取 JWT
TOKEN=$(curl -s -X POST $BASE/auth/login -H "Content-Type: application/json" \
  -d '{"email":"demo@example.com","password":"pass123456"}' | jq -r '.token')
AUTH="Authorization: Bearer $TOKEN"

# 3) 创建知识库
KB_ID=$(curl -s -X POST $BASE/knowledge-bases -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"name":"我的知识库","description":"demo","type":"document"}' | jq -r '.data.id')

# 4) 初始化知识库（本地 Ollama 示例；远程模型改 source/baseUrl/apiKey）
curl -s -X POST $BASE/initialization/initialize/$KB_ID -H "$AUTH" -H "Content-Type: application/json" -d '{
  "llm":       {"source":"local","modelName":"qwen3:8b"},
  "embedding": {"source":"local","modelName":"bge-m3","dimension":1024},
  "rerank":    {"enabled":false},
  "multimodal":{"enabled":false},
  "documentSplitting":{"chunkSize":512,"chunkOverlap":80,"separators":["\n\n","\n","。"]},
  "nodeExtract":{"enabled":false},
  "questionGeneration":{"enabled":false}}'

# 5) 上传文档（multipart，字段名 file）
curl -s -X POST $BASE/knowledge-bases/$KB_ID/knowledge/file -H "$AUTH" -F "file=@./demo.pdf"
# 轮询解析状态：GET /knowledge-bases/$KB_ID/knowledge 至 parse_status=completed

# 6) 创建会话
SESSION_ID=$(curl -s -X POST $BASE/sessions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"title":"第一次对话"}' | jq -r '.data.id')

# 7) 快速问答（SSE 流式）
curl -N -X POST $BASE/knowledge-chat/$SESSION_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"query":"这份文档讲了什么？","knowledge_base_ids":["'$KB_ID'"]}'

# 7b) 智能推理（SSE；agent_id 可取 builtin-smart-reasoning）
curl -N -X POST $BASE/agent-chat/$SESSION_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"query":"总结文档要点并列出依据","agent_enabled":true,"agent_id":"builtin-smart-reasoning","knowledge_base_ids":["'$KB_ID'"]}'

# 8) 仅检索不生成（结构化 JSON）
curl -s -X POST $BASE/knowledge-search -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"query":"关键字","knowledge_base_ids":["'$KB_ID'"]}'
```

### 三种认证方式

| 方式 | 请求头 | 适用 |
|------|--------|------|
| JWT | `Authorization: Bearer <token>` | 浏览器 / 交互式调用 |
| API Key（推荐用于服务端） | `X-API-Key: <key>` | 程序化集成；「空间设置 → API Key」创建，可勾选细粒度能力并限定知识库范围 |
| 指定空间 | `X-Tenant-ID: <id>` | 多空间用户切换当前工作空间 |

> 服务端集成建议用 API Key 而非 JWT（长期有效、权限可控）。完整 API 清单见官方 Swagger（debug 模式 `http://<host>:8080/swagger/index.html`）与开发者文档站。
