# WeKnora 开发模式运行方式与项目结构梳理（20260929-01）

> 目的：梳理 WeKnora 当前"正常"的开发运行方式（`make dev-app` 形态），并复核项目结构、
> 依赖链路、端口、关键配置，作为后续开发与排障的基线文档。
> 实测环境：本机（mk1 / Ubuntu 22.04 x86_64，Docker Desktop 类环境），分支工作副本位于
> `$HOME/workspace/WeKnora`，数据库名 `weknora_mdev`（mdev 工作分支）。

## 1. 一句话概览

**开发模式 = Docker 只跑"基础设施"，Go 后端与前端跑在宿主机本地进程。**

- `make dev-start` → `docker compose -f docker-compose.dev.yml --profile minio --profile langfuse up -d`
  拉起 postgres / redis / docreader / minio / langfuse（web+worker+clickhouse+minio）等容器。
- `make dev-app` → 宿主机上 `go run ./cmd/server` 启动后端（检测到 anydoc 静态库时自动
  加 `-tags anydoc`；若装了 air 则走热重载）。
- `make dev-frontend` → 宿主机上 `frontend/` 下 `npm run dev`（Vite，端口 5173，
  将 `/api` 等代理到后端）。

生产/一体化形态则是 `docker-compose.yml`（或 `scripts/start_all.sh`）把 app、frontend、
docreader 连同全部依赖一起容器化；另有 Lite 模式（`make build-lite` / `run-lite`，
SQLite + 内存队列单二进制，零外部依赖）。

| 目录 | 说明 |

| `docker-compose.yml` | 生产/全量一体化编排（app+frontend+全部依赖+可选向量库/图数据库/langfuse/searxng 等 profile） |

## 3. 开发模式运行链路（当前正常方式）

### 3.1 启动顺序

```bash
# 终端 1：基础设施（幂等，可重复执行）
make dev-start                    # = ./scripts/dev.sh start
# 可选参数: --qdrant --neo4j --dex --odl-hybrid --full 等

# 终端 2：后端
make dev-app                      # = ./scripts/dev.sh app

# 终端 3：前端
make dev-frontend                 # = ./scripts/dev.sh frontend
```

`dev.sh start` 的默认 profile 是 `minio + langfuse`：
- **minio 默认必开**：`.env` 中 `STORAGE_TYPE=minio` 时后端启动 `initFileService` 会
  检查 bucket，缺 MinIO 直接 panic。
- **langfuse 默认开**（LLM 可观测），可用 `--no-langfuse` 关闭。
- 其余（qdrant / opensearch / milvus / neo4j / dex / searxng / odl-hybrid）按需 profile 启用。
- 设置 `DEV_REMOTE_HOST=<ip>` 可切"远程开发模式"：跳过本地 Docker，基础设施指向远程
  机器的 5432/6379/50051/9000 等端口。

`dev.sh app`（即 `make dev-app`）做的事：
1. 校验 Go 可用；加载 `.env`（+ `.env.local` 覆盖，去 CRLF）。
2. **把容器服务名强制改写为宿主机回环地址**（非远程模式时）：
   `DB_HOST=127.0.0.1`、`REDIS_ADDR=127.0.0.1:6379`、`DOCREADER_ADDR=127.0.0.1:50051`、
   `MINIO_ENDPOINT=127.0.0.1:${MINIO_PORT:-9009}`、`MILVUS_ADDRESS=127.0.0.1:19530`、
   `NEO4J_URI=bolt://127.0.0.1:7687`、`QDRANT_HOST=127.0.0.1`。
   这一步是关键：`.env` 里写的 `minio:9000`/`docreader:50051` 是容器内服务名，
   本地进程必须走宿主机映射端口。
3. 连通性检查（nc 探测 PG/Redis/DocReader 端口），失败即退出并给排查提示。
4. `LOCAL_STORAGE_BASE_DIR` 若未设或为 `/data/files`（容器路径），自动改为
   `$PROJECT_ROOT/.local-data/files` 并 `mkdir -p`。
5. 检测 anydoc 静态库（`third_party/anydoc-go/lib/<target>/libanydoc_go.a`，
   由 `make anydoc-lib` 构建）→ 自动加 `GO_BUILD_TAGS=anydoc`。
6. 有 air 用 air（热重载）；否则 `go run -tags ... -ldflags=... ./cmd/server`
   （ldflags 注入 Version/Edition/CommitID 等构建信息 + protobuf `conflictPolicy=warn`）。

### 3.2 停止 / 日志 / 状态 / 依赖

```bash
make dev-stop        # dev.sh stop：全量 profile 超集 down，保证残留清干净
make dev-status      # compose ps
make dev-logs        # compose logs -f（看基础设施；后端日志在本地终端里）
./scripts/dev.sh start --neo4j    # 按需加开可选服务
```

### 3.4 端到端请求链路

```
浏览器 → http://localhost:5173 (Vite)
       → /api/* 代理 → http://localhost:8080 (本地 go server)
                      ├→ 127.0.0.1:5432  PostgreSQL/ParadeDB（元数据+向量+全文）
                      ├→ 127.0.0.1:6379  Redis（队列/缓存/流式事件）
                      ├→ 127.0.0.1:9009  MinIO（对象存储 STORAGE_TYPE=minio）
                      ├→ 127.0.0.1:50051 DocReader gRPC（文档解析）
                      └→ LLM: Ollama / 云端模型（.env 配置）
可观测  → http://localhost:3000 Langfuse（LANGFUSE_HOST）
```

## 4. 与生产/一体化模式的对照

| 维度 | 开发模式（当前） | 生产 docker-compose.yml | Lite 模式 |
|---|---|---|---|
| app | 本地 `go run`（8080） | 容器 `wechatopenai/weknora-app` | 同二进制，SQLite FTS5 |
| frontend | 本地 Vite（5173） | 容器 `wechatopenai/weknora-ui`（nginx，镜像内代理到 app:8080，对外 80） | 前端静态文件内嵌 `web/` |
| 依赖 | compose.dev 基础设施 | 同一 compose 内全部依赖（含可选向量库/图库/searxng/opensearch 等 profile） | 无外部依赖（SQLite+内存队列） |
| 数据落盘 | 容器 named volume / `.local-data/files` | named volume / bind mount | 单目录 |
| 命令 | `make dev-start/dev-app/dev-frontend` | `make docker-build-all && make docker-run` 或 `make start-all` | `make build-lite` / `run-lite` / `package-lite` |

## 5. 常见坑与注意事项

1. **端口**：本地后端实际监听 8080（config.yaml），不是 .env 里的 `APP_PORT=8081`。
   改端口：`config/config.yaml` `server.port`；前端代理目标随之用
   `VITE_DEV_PROXY_TARGET` 覆盖。
2. **`dev-app` 前必须先 `dev-start`**：否则 PG/Redis/DocReader 探测不通过直接退出；
   PG 刚起时要等 healthcheck（~30s start_period）。
3. **STORAGE_TYPE=minio 时必须起 minio**（dev-start 默认已带），否则后端 panic。
4. **`LOCAL_STORAGE_BASE_DIR=/data/files` 只在容器里成立**；dev.sh app 会自动改写为
   `.local-data/files`。不要手工设成不存在的宿主机路径。
5. **anydoc 静默降级**：只有 `make anydoc-lib` 构建过静态库时 dev-app 才带 `-tags anydoc`
   （进程命令行里出现 `-tags anydoc` 即说明生效）；没有则 Office 解析走 docreader 容器。
6. **air 热重载**：装了 air 后 dev-app 行为改变（编译+重启循环），排障时留意日志格式不同。
7. **`.env` 里的容器服务名**（`minio:9000`、`docreader:50051` 等）本地进程不可达，
   dev.sh 已统一改写；若绕过 dev.sh 直接跑 `go run`，必须自行 export 127.0.0.1 地址。
8. **数据目录两种模式**（dev-named-volume.sh vs dev-host-data.sh，由
   `WEKNORA_DEV_DATA_MODE` 控制）：后者把数据放仓库内 `.local-data/dev-compose`，
   注意权限。当前使用默认 named volume 模式。
9. **stop 用全量 profile 超集**：`dev-stop` 会顺带 down langfuse/minio 等，
   即使你 start 时没带这些 profile（防止残留占网）。
10. **远程开发**：`.env.local` 里设 `DEV_REMOTE_HOST=<ip>` 即可让本地 app 连远程基础设施，
    本地不再需要 docker。

## 6. 后端入口与启动流程（cmd/server）

`cmd/server/main.go` 核心流程：

1. 加载配置：`config/config.yaml`（server host/port、日志、功能开关）+ `.env` 环境变量
   （`internal/config` 里 env 优先或 yaml 优先以代码实现为准；端口来自 yaml 的
   `server.port`）。
2. 初始化数据库（postgres，自动跑 migrations / 版本检查，见 `scripts/migrate.sh` 与
   `migrations/`）。
3. 初始化 Redis（STREAM_MANAGER_TYPE=redis：任务队列、流式事件通道）。
4. 初始化对象存储（STORAGE_TYPE=minio/local/cos/tos...）。
5. 初始化 DocReader 客户端（gRPC，`DOCREADER_TRANSPORT`）、检索驱动
   （RETRIEVE_DRIVER=postgres|qdrant|milvus|opensearch|...）。
6. 启动 GIN HTTP 服务：`addr := cfg.Server.Host:cfg.Server.Port`；带优雅停机
   （先关 listener 再 drain）。
7. 版本/构建信息来自 ldflags 注入（`internal/handler.Version` 等），
   由 `scripts/get_version.sh` 从 git 元数据生成。

主要 Makefile 目标（开发常用）：

| 命令 | 说明 |
|---|---|
| `make dev-start / dev-stop / dev-restart` | 基础设施 up/down（dev.sh 封装） |
| `make dev-app` | 本地后端（dev.sh app） |
| `make dev-frontend` | 本地前端 Vite |
| `make dev-status / dev-logs` | 容器状态 / 日志 |
| `make anydoc-lib` | 构建 anydoc Rust 静态库（需 Rust 工具链） |
| `make build-anydoc` | 带 anydoc tag 的静态构建 |
| `make migrate-up / migrate-down` | 数据库迁移 |
| `make docs` | swag 生成 Swagger（访问 `/swagger/index.html`） |
| `make build-prod` | 生产静态构建（ldflags 注入版本、strip 符号） |
| `make build-lite / run-lite / package-lite` | Lite 单二进制 |
| `make docker-build-all / docker-run / docker-restart` | 全量容器化 |
| `make clean-db` | 删 postgres/minio/redis 的 docker volume（慎用） |

## 7. 排障速查

| 现象 | 排查方向 |
|---|---|
| `dev-app` 报"数据库未就绪" | `make dev-status` 看 postgres healthcheck；刚 `dev-start` 需等 ~30s |
| 后端起了但 5173 页面 502/404 | 确认 8080 在监听：`ss -ltnp \| grep 8080`；前端代理目标是否 8080 |
| 解析文档失败 | docreader 容器是否 healthy（`grpc_health_probe`）；`docker logs WeKnora-docreader-dev` |
| 启动即 panic（minio bucket） | minio 未起：`make dev-start`（默认带 minio profile） |
| 文件保存报错 | `LOCAL_STORAGE_BASE_DIR` 是否可写（自动为 `.local-data/files`） |
| LLM 调用失败 | `.env` 的 Ollama/云端模型配置；注意 `host.docker.internal` 在纯本地 go 进程里不可用，本地应写 `127.0.0.1` |
| Office 解析缺引擎 | 进程是否带 `-tags anydoc`；没有则 `make anydoc-lib` 后重启 dev-app |
| Langfuse 无数据 | `LANGFUSE_HOST=http://localhost:3000` + PK/SK 是否在 `.env`/`.env.local` |

## 8. 结论

当前"正常"的开发运行方式即：**`make dev-start`（Docker 基础设施）+ `make dev-app`
（本地 go 后端，:8080）+ `make dev-frontend`（本地 Vite，:5173，代理 → :8080）**。
三者在宿主机通过回环地址/发布端口连通，数据落 docker named volume 与
`.local-data/files`。该方式已稳定运行（基础设施 6 天未重启，后端 9-28 起，前端 9-24 起）。
