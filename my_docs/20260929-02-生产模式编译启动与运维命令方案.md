> 基于 2026-09-29 对 `Makefile`、`docker-compose.yml`（1027 行）、`scripts/start_all.sh`、
> `scripts/build_images.sh`、`scripts/dev.sh` 的逐段核实用法。

## 1. 直接回答两个问题

### Q1：生产模式要不要先 `make dev-start`？

**不需要，也不建议。** 两套编排完全独立：

| | 开发模式 | 生产模式 |
|---|---|---|
| 编排文件 | `docker-compose.dev.yml` | `docker-compose.yml` |
| 基础设施（postgres/redis/docreader…） | `make dev-start` 拉起，`WeKnora-*-dev` 容器，named volume `*-dev` | **`docker-compose up` 时由 compose 自己按需 `depends_on` 拉起**，`WeKnora-postgres`/`WeKnora-redis`/`WeKnora-docreader` 等容器，volume `weknora_postgres-data` 等 |
| app / frontend | 宿主机本地进程 | 容器 `WeKnora-app` / `WeKnora-frontend`（`wechatopenai/weknora-app` / `wechatopenai/weknora-ui` 镜像） |

实测 `docker compose -f docker-compose.yml config --services`（默认集合，无 profile）=
**redis, docreader, postgres, app, frontend** 五个服务 —— 生产模式的 postgres/redis/docreader
就是这份 compose 自带的服务，`app` 通过 `depends_on`（postgres healthy、docreader healthy、
redis started）自动等待依赖就绪，**不存在需要另外 `make dev-start` 的前置步骤**。

⚠️ **两套容器不能同时启动**：都发布宿主机 5432（postgres）、6379（redis）、9009（minio）、
50051（docreader dev 版发布、生产版只 expose 不发布）、80（frontend 生产版发布 80）。
端口冲突会导致生产容器起不来或行为错乱。切换模式前先停掉另一套。
数据也互相隔离（volume 名不同），但数据库名若相同（都叫 `weknora_mdev`）容易误连，
建议生产 `.env` 用不同的 `DB_NAME`。

> ✅ **已落实（2026-09-29）**：`.env` 切为生产值（`DB_HOST=postgres`、
> `DB_NAME=weknora_prod`），dev 侧用 `.env.local` 覆盖回 `DB_HOST=localhost` /
> `DB_NAME=weknora_mdev`（`scripts/dev.sh` 的 `load_env_files` 后 source `.env.local`），
> dev 容器卷内旧库已初始化（`POSTGRES_DB` 仅空卷生效），dev 数据不受影响。

### Q2：容器停止 / 日志用哪个命令？

见 §5 命令速查表。核心：`make docker-stop`（= `docker-compose down`，容器删、volume 留）；
日志 `docker compose logs -f <服务>` 或 `make start-all` 末尾会自动 tail
`app docreader postgres` 三个容器日志。

## 2. 生产模式架构与启动链

```
浏览器 → http://<host>:${FRONTEND_PORT:-80}  (WeKnora-frontend: nginx 镜像 weknora-ui)
       → nginx 按 APP_HOST=app / APP_PORT=${APP_BACKEND_PORT:-8080} 反代
       → WeKnora-app (weknora-app:8080, env_file: .env + compose environment)
          ├ depends_on: postgres(service_healthy) / docreader(service_healthy) / redis(started)
          ├→ WeKnora-postgres (paradedb pg17, port ${DB_PORT:-5432})
          ├→ WeKnora-redis (port ${REDIS_PORT:-6379})
          ├→ WeKnora-docreader (gRPC 50051, 仅 compose 网络内 expose，不发布宿主机)
          ├→ MinIO/COS/TOS/local …（STORAGE_TYPE 决定；minio 在 compose 里是 profile，非默认）
          └→ LLM（Ollama / 云端模型配置）
可选 profile：searxng / minio / qdrant / milvus / weaviate / doris-fe+be / neo4j / dex /
            langfuse(web+worker+clickhouse+minio+db-init) / odl-hybrid / sandbox(仅 build,pull)
```

关键点（与开发模式的差异）：

1. **config.yaml 被挂载进容器**：`./config/config.yaml:/app/config/config.yaml`，
   `server.port: 8080` 对 app 容器生效（容器内固定 8080，宿主机端口由 `APP_PORT` 控制：
   `${APP_PORT:-8080}:8080`）。nginx 反代目标 = 容器名 `app` + `APP_BACKEND_PORT`。
2. **`.env` 通过 `env_file` 原样注入 app 容器**，且 compose `environment:` 段落覆盖同名变量。
   所以容器内 `DB_HOST=postgres`、`DOCREADER_ADDR=docreader:50051` 这类**服务名寻址天然成立**——
   开发模式里要改写成 127.0.0.1 的问题在生产模式不存在。
3. **`.env` 必须存在**：compose 用了 `env_file: [.env]`（老版本兼容写法），缺失会导致
   `docker compose config` 直接报错。`make docker-run` / `make start-all` 都有 `.env`
   不存在时自动 `cp .env.example .env`（或 `touch`）的预检。
4. **迁移**：app 启动时默认 `AUTO_MIGRATE=true` 自动跑 migrations；也可手动
   `make migrate-up / migrate-version`。
5. **沙箱镜像**：`WeKnora-sandbox` 非常驻，Agent Skills 执行时由 app 按需 `docker run`；
   `start_all.sh` 启动后会预拉取该镜像（`ensure_sandbox_image`）。

## 3. 编译（构建镜像）

```bash
# 一条命令构建全部三个镜像（app + docreader + frontend）
make docker-build-all

# 或单独构建（改了哪层建哪层，省时间）
make docker-build-app        # wechatopenai/weknora-app:latest   （docker/Dockerfile.app）
make docker-build-docreader  # wechatopenai/weknora-docreader:latest
make docker-build-frontend   # wechatopenai/weknora-ui:latest     （先跑 scripts/build_frontend_dist.sh）
```

细节：
- 版本信息（VERSION / COMMIT_ID / BUILD_TIME / GO_VERSION）由 `scripts/get_version.sh`
  从 git 读取并通过 `--build-arg` 注入，ldflags 烙进二进制。
- `WITH_ANYDOC=1`（默认）会把 Office 解析引擎（anydoc，Rust 静态库）打进 app 镜像；
  想瘦身可 `make docker-build-app WITH_ANYDOC=0`。
- 等价于直接跑 `./scripts/build_images.sh`（`-a/-p/-d/-f/-s/-c` 对应 all/app/docreader/
  frontend/sandbox/clean），支持 `GOPROXY/GOSUMDB/GOPRIVATE` build-arg。
- **只改前端**时走 `docker-build-frontend` 即可，不必重建 app。
- 拉取官方镜像而不自建时：`make pull-images` 或 `make start-all`（默认 `--pull`）。

## 4. 启动

### 方式 A：make 直连 compose（最透明，推荐自建镜像场景）

```bash
# 首次
make docker-build-all
make docker-run            # = 预检 .env 存在 → docker-compose up（前台构建不存在的，-d 后台）

# 已有镜像，只起容器
docker compose up -d
docker compose ps          # 看状态
```

`make docker-run` 的 `up` **不带 `--pull`**，用你刚 build 出来的本地 `latest`——这是
"自建镜像上生产"的正确路径。

### 方式 B：start_all.sh（一体化脚本，`make start-all`）

```bash
make start-all             # = ./scripts/start_all.sh          （Ollama + Docker，默认 --pull）
make start-all NO_PULL=1   # 脚本支持 --no-pull 语义：仅本地镜像，不拉官方 latest（自建镜像必须）
./scripts/start_all.sh --docker        # 只起 Docker，不管 Ollama
./scripts/start_all.sh --check         # 环境诊断（环境检查、容器状态）
./scripts/start_all.sh --list          # 列出运行中容器
```

⚠️ **自建镜像务必用 --no-pull**：`start_all.sh` 的 `start_docker` 默认执行
`docker compose up --pull always -d`，会去 registry 拉 `wechatopenai/weknora-app:latest`
**覆盖/替换你刚 build 的本地 latest**，导致跑的并不是自己的代码。两条安全路径：
- `make docker-run`（方式 A，无 pull）；
- 或 `./scripts/start_all.sh --docker --no-pull`。
（只有部署"官方镜像 + .env.example 默认"的纯配置化部署才走默认 pull。）

启动后 `start_all.sh` 会：检查容器状态 → 预拉取 sandbox 镜像 → 持续 tail
`app docreader postgres` 日志（Ctrl+C 只退出日志，不停容器）。

## 5. 重启 / 停止 / 日志 命令速查

| 操作 | 命令 | 说明 |
|---|---|---|
| **重启全部** | `make docker-restart` | = `docker-compose stop -t 60 && docker-compose up`：**只重建已停止的容器，不重新 build**。改了代码请先 `make docker-build-*` 再 `docker compose up -d --force-recreate <服务>` |
| **重启单个服务** | `docker compose up -d --force-recreate app` | 最常用：重建 app 容器（换镜像后、改 config.yaml 挂载后） |
| **停（保留 volume）** | `make docker-stop` | = `docker-compose down`，删容器和网络，数据 volume 保留 |
| **停（含 Ollama）** | `make stop-all` | = `start_all.sh --stop`，stop docker + 宿主 Ollama |
| **删数据（危险）** | `make clean-db` | 直接 `docker volume rm` postgres/minio/redis 数据卷，不可恢复 |
| **查状态** | `docker compose ps` | 健康状态、端口映射一目了然 |
| **全部日志** | `docker compose logs -f` | 跟踪所有服务 |
| **按服务日志** | `docker compose logs -f app` | `app` / `docreader` / `postgres` / `redis` / `frontend` / `minio`… |
| **按时间/行数** | `docker compose logs --since 10m -n 200 app` | 最近 10 分钟 / 尾 200 行 |
| **单容器原生** | `docker logs -f --tail 200 WeKnora-app` | 容器名：`WeKnora-app`、`WeKnora-frontend`、`WeKnora-docreader`、`WeKnora-postgres`…（注意**无 -dev 后缀**） |
| **进容器排查** | `docker exec -it WeKnora-app sh` | app 内可用 `psql`/`curl http://localhost:8080/health` |
| **诊断** | `make check-env` | `start_all.sh --check` 环境体检 |

## 6. 典型上线操作序列

### 6.1 首次部署（自建镜像，从当前 mdev 分支）

```bash
cd "$HOME/workspace/WeKnora"
# 0) 若开发容器在跑，先停（避免 5432/6379 端口冲突）
make dev-stop

# 1) 生产配置：.env 已切为生产值（DB_HOST=postgres / DB_NAME=weknora_prod，2026-09-29）；
#    dev 本地连接由 .env.local 覆盖（DB_HOST=localhost / DB_NAME=weknora_mdev）。
#    首次启动前确认 DB_USER/PASSWORD、TENANT_AES_KEY/JWT_SECRET、LLM 配置、
#    DISABLE_REGISTRATION=true 等必填项（cp .env .env.prod-backup 视情况留备份）

# 2) 构建镜像（含 anydoc）
make docker-build-all

# 3) 启动（不 pull，用本地镜像）
make docker-run

# 4) 验收
docker compose ps                                   # 全部 Up (healthy)
curl -fsS http://localhost:8080/health              # app 健康
curl -s -o /dev/null -w '%{http_code}\n' http://localhost/   # frontend → 200
docker compose logs app | grep -iE 'migrat|error|panic' | tail -20
```

### 6.2 日常发版（代码更新 → 换镜像 → 重建容器）

```bash
git pull   # 或切到目标 commit
make docker-build-app           # 改了什么建什么；全量 make docker-build-all
docker compose up -d --force-recreate app          # 换新镜像
docker compose up -d --build frontend docreader -d # 或整组：
docker compose up -d                     # 让 depends_on 链路收敛
docker compose ps && docker compose logs --since 2m app docreader
```

> 更简单粗暴但完全正确：`make docker-build-all && make docker-restart`
> （restart 前 compose up 会发现镜像变化，重建带新镜像的容器；对"同 tag 新 layer"
> 场景建议显式 `--force-recreate` 更可靠。）

### 6.3 停机维护 / 重启

```bash
make docker-stop                            # 停（数据保留）
docker compose up -d                        # 再启
# 需要重建镜像时： make docker-build-all && docker compose up -d --force-recreate
```

## 7. 可选 profile 与常见配置决策

| profile（`docker compose --profile xxx up -d`） | 何时需要 |
|---|---|
| `searxng` | 需要联网搜索（SearXNG 聚合搜索） |
| `minio` | `STORAGE_TYPE=minio` 且想用 compose 自带 MinIO 而非外部对象存储 |
| `qdrant` / `milvus` / `weaviate` / `doris` | `RETRIEVE_DRIVER` 换/加对应向量库（默认 postgres 不用） |
| `neo4j` | `ENABLE_GRAPH_RAG=true`（当前 .env 为 false，不用） |
| `dex` | OIDC 企业登录（`OIDC_AUTH_ENABLE=true`） |
| `langfuse` | 生产也用自建 Langfuse 观测（.env 配 PK/SK） |
| `odl-hybrid` | docreader 切 OpenDataLoader/Docling 解析（docreader 需 `DOCREADER_ODL_HYBRID=docling-fast`） |
| `full`（dev 侧语义，生产用各 profile 组合） | 全开 |

生产 `.env` 必改项清单（对照 dev 经验）：
- `DB_NAME` / `DB_USER` / `DB_PASSWORD`：生产独立库（✅ 已改为 `weknora_prod`；
  `DB_PASSWORD` 仍为弱口令，建议上正式部署前换 `openssl rand -base64 24` 强密码）；
- `STORAGE_TYPE`：生产建议 COS/TOS/外部 MinIO（内网），而非 dev 自带容器；
- `LOG_LEVEL=info`、`GIN_MODE=release`（生产建议；dev .env 已 release）；
- `DISABLE_REGISTRATION=true`；`JWT_SECRET`/`TENANT_AES_KEY`/`SYSTEM_AES_KEY` 用生产随机值；
- LLM：`OLLAMA_BASE_URL` 等指向真实推理服务（`host.docker.internal` 在容器内可用，
  指向宿主 Ollama 即可，与开发模式不同）；
- 如需对外提供 IM 图片外链：`APP_EXTERNAL_URL` 或 MinIO 公网 endpoint；
- 端口：`FRONTEND_PORT`/`APP_PORT` 避开本机其他服务（本机常见 80 被 hlsa 其他项目占用，
  部署前 `ss -ltn | grep ':80 '` 确认）。

## 8. 排障速查（生产模式）

| 现象 | 排查 |
|---|---|
| `docker compose up` 报 .env 解析错误 | `.env` 缺失或 `${VAR}` 未定义（新 clone 先 `cp .env.example .env`） |
| app 一直 starting / unhealthy | `docker compose logs app`：多为 DB 密码错、迁移失败、minio bucket 不存在（`make check-env`）；postgres 需先 healthy（`docker compose ps`） |
| docreader unhealthy 拖住 app | `docker compose logs docreader`；`docker exec WeKnora-app` 内 `grpc_health_probe -addr=docreader:50051` |
| 前端 502 | app 容器未 healthy（frontend `depends_on app: service_healthy`）；或 `APP_BACKEND_PORT` 配错 |
| 跑成了官方镜像而不是自己编译的 | 用了 `start_all.sh` 默认 `--pull always`；改 `--no-pull` 或 `make docker-run` |
| 80/8080 端口冲突 | 与 dev 容器或其他主机服务冲突：先 `make dev-stop`，或 `.env` 改 `FRONTEND_PORT`/`APP_PORT` |
| 数据卷权限/磁盘 | `docker volume ls`（weknora_* 系列）；`docker compose down -v` 会删 volume（危险） |

## 9. 结论

- 生产上线路径：**`make docker-build-all` → `make docker-run`（或 `start_all.sh --docker --no-pull`）
  → `docker compose ps` 验收**。全套基础设施（postgres/redis/docreader）由
  `docker-compose.yml` 自带，**与 `make dev-start` 完全无关、不要混跑**。
- 重启：`make docker-restart` / 单服务 `docker compose up -d --force-recreate <svc>`；
  停止：`make docker-stop`；日志：`docker compose logs -f [svc]` 或 `docker logs WeKnora-<svc>`。
