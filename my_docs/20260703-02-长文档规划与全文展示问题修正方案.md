# 长文档规划与全文展示问题修正方案

## 1. 背景与目标

本次专项审查针对以下 5 个长文档页面问题：

1. 长文档在生成正文前，没有像现有工具调用组件一样显示当前步骤与结果。
2. 规划阶段没有稳定通过独立控件显示文档大纲，且要求在完成前就可见。
3. 长文档生成完成后，文档版本卡片不会自动出现，必须刷新页面后才显示。
4. 长文档生成结束后，文档规划控件仍显示“收尾中”，没有正确收口为完成态。
5. 对某章节续写后，点击“查看全文”，没有真正接入完整文档显示流程。

本文基于当前代码实现进行专项审查，目标不是重新设计一套长文档系统，而是在当前架构上明确：

- 哪些能力已经存在；
- 哪些链路当前不完整或不准确；
- 应该如何修正，才能让长文档 live 展示、规划控件、版本卡片、全文查看四条链路稳定收口。

## 2. 审查结论

结论先行：

当前长文档相关实现已经具备三类基础能力：

1. **后端长文档执行能力已存在**：包括完整文档生成、基于 artifact 的续写/修订、artifact 版本链、generation run、planning outline、全文快照。
2. **前端长文档独立区域已初步接入**：包括规划大纲面板、版本卡片、版本链抽屉、基线横幅。
3. **P2 的一部分后端收敛已经开始**：例如 `long_document_enabled`、`planning_outline`、历史消息 replay metadata、版本链 root 查询能力已进入代码。

但当前实现**仍然不完整，也不够准确**。主要问题不在“有没有长文档能力”，而在于：

- **live 规划展示链路**与**artifact 持久化展示链路**仍然分裂；
- **规划阶段用 synthetic thinking 事件承载，但现有 Agent 页面在 live 阶段把这类事件隐藏掉**；
- **artifact 元数据是在 completion 持久化后才稳定产生，但当前前端版本卡片只消费 live complete 里的 artifact**；
- **查看全文只切换了数据源，没有真正把完整预览区打开**；
- **规划面板的状态机只看“最后一条 progress thought 的 stage”，没有被 terminal complete 事件纠正**。

因此，当前代码对这 5 个问题的覆盖状态可以概括为：

| 问题 | 当前状态 | 结论 |
| --- | --- | --- |
| 正文前步骤/结果展示 | 有进度事件，但 live 阶段被隐藏 | 不完整 |
| 完成前规划大纲控件展示 | 有 outline 数据和面板，但显示时机与位置不稳定 | 不完整 |
| 完成后自动出现版本卡片 | refresh 后可见，live 完成后不可见 | 不准确 |
| 规划状态从“收尾中”收口为完成 | 当前不会自动收口 | 不准确 |
| 点击“查看全文”显示整文 | 只切换模式，不保证真正展开完整内容 | 不完整 |

## 3. 当前代码根因分析

### 3.1 问题一：正文前没有显示“步骤与结果”

#### 现象

用户期望在正文生成前，像普通 Agent 工具调用一样，先看到“搜索关键词”“检索知识库”“规划大纲”等步骤与结果。

#### 当前代码审查

前端主展示逻辑在以下位置：

- `frontend/src/views/chat/components/AgentStreamDisplay.vue`
- `frontend/src/views/chat/long-document/components/LongDocumentMessageEnhancements.vue`
- `frontend/src/views/chat/long-document/useLongDocumentPlanning.ts`

当前长文档后端规划/检索进度主要通过 **synthetic thinking 事件**发送：

- `fullDocumentProgressReporter.UpdateStage`
- `fullDocumentProgressReporter.PublishOutline`
- document_edit / continuation / full_document 路径中的 `EventAgentThought`

但是 `AgentStreamDisplay.vue` 当前有两个明确的过滤行为：

1. `visibleIntermediateEvents` 会把 `thinking` 事件全部过滤掉。
2. `displayEvents` 在 `!isConversationDone` 时也会把 `thinking` 事件全部过滤掉。

而长文档规划/检索阶段当前大多数不是实际 `tool_call/tool_result`，而是 synthetic `thinking` 进度，因此：

- 后端明明发了进度；
- 前端 live 阶段却主动把它隐藏；
- 最终用户看到的是“没有步骤，直接出正文”或“只看到 loading dots”。

#### 根因结论

**当前长文档 live 阶段复用了 AgentStreamDisplay，但长文档进度事件的数据形态与 AgentStreamDisplay 的 live 展示过滤规则不匹配。**

### 3.2 问题二：规划大纲没有在完成前稳定显示

#### 现象

用户希望规划阶段就看到独立的“文档规划”控件与大纲内容，而不是完成后才显示，或只能在刷新后恢复。

#### 当前代码审查

规划面板当前由以下链路控制：

- `frontend/src/views/chat/long-document/components/LongDocumentMessageEnhancements.vue`
- `frontend/src/views/chat/long-document/useLongDocumentPlanning.ts`
- `frontend/src/views/chat/long-document/components/LongDocumentOutlinePanel.vue`

当前 `LongDocumentMessageEnhancements.vue` 只有在：

- `session.long_document_enabled === true`

时才挂载。

当前 `useLongDocumentPlanning.ts` 的 `visible` 条件是：

- `session.long_document_enabled === true`
- 且 `(outline || isPlanningLive)`

这里有两个问题：

1. **规划控件挂载位置在 `AgentStreamDisplay` 之后**，而不是与 live 步骤区一体化展示，所以即使显示，也不符合截图中的层次关系。
2. 规划大纲当前主要依赖 `thinking` 事件里的 `outline/planning_outline`，但 live 阶段 `thinking` 本身在主时间线里被隐藏，造成“规划数据有了，但上下文氛围不对，页面看起来像没进入规划阶段”。

#### 根因结论

**大纲面板本身并不是完全缺失，而是当前挂载位置、live 事件可见性、以及 planning/runtime 区域的组合方式不符合目标交互。**

### 3.3 问题三：完成后版本卡片不自动显示，刷新后才显示

#### 现象

长文档生成完成后，截图 2 中的“文档版本”卡片不会立即出现，刷新页面后才出现。

#### 当前代码审查

前端版本卡片当前依赖：

- `session.chat_document_artifact`
- `LongDocumentMessageEnhancements.vue` 中的 `artifact`

后端 live complete 事件来自：

- `internal/application/service/session_agent_qa.go` 中的 `emitFullDocumentCompletion` / document_edit completion
- `internal/handler/session/agent_stream_handler.go` 中的 `handleComplete`

但 artifact 的真正注册发生在更后面的持久化路径：

- `internal/handler/session/qa.go` 的 `completeAssistantMessageInPlace`
- `AggregateDocumentGenerationArtifact`

也就是说当前链路是：

1. 模型完成，先发 `agent.complete`。
2. 前端收到 complete，但此时 `chat_document_artifact` 往往还没稳定注册。
3. 后端随后才注册 artifact。
4. 前端当前没有“artifact 注册完成后再补一条元数据回推”的机制。
5. 刷新页面后，历史消息加载会通过 source_message_id 再把 artifact 补回，因此卡片才出现。

#### 根因结论

**版本卡片缺失不是前端不渲染，而是 live complete 与 artifact 持久化完成之间没有二次同步。**

### 3.4 问题四：生成结束后规划面板仍显示“收尾中”

#### 现象

长文档已经完成，但规划控件右上角仍显示“收尾中”。

#### 当前代码审查

状态来源：

- `useLongDocumentPlanning.ts` 的 `latestProgressEvent`
- `LongDocumentOutlinePanel.vue` 的 `stageText`

当前实现中：

- `stage` 只取“最后一条 `thinking` progress event”的 `stage`。
- 如果最后一条 progress 是 `finalizing`，而之后没有新的 planning/progress thought 覆盖它，面板就会一直停留在 `finalizing`。
- `agent_complete` 事件当前虽然带有 terminal completion 信息，但 `useLongDocumentPlanning.ts` 没有用 terminal 状态反推 planning 状态收口。

#### 根因结论

**规划面板缺少“terminal complete 覆盖 live progress stage”的状态机收口逻辑。**

### 3.5 问题五：点击“查看全文”没有真正显示整文

#### 现象

对第三章续写后，点击“查看全文”，没有进入完整文档显示流程。

#### 当前代码审查

关键控件与链路：

- `frontend/src/views/chat/components/ChatDocumentArtifactCard.vue`
- `frontend/src/views/chat/long-document/useLongDocumentArtifacts.ts`
- `frontend/src/views/chat/long-document/components/LongDocumentMessageEnhancements.vue`
- `frontend/src/views/chat/index.vue` 中的 `handleArtifactDisplayUpdate`

当前 `ChatDocumentArtifactCard.vue` 分两种按钮路径：

1. `canToggleDocumentDisplay=true` 时，按钮直接 `emit('toggle-document-display')`
2. 只有 `canToggleDocumentDisplay=false` 且 `canViewDocument=true` 时，才会走 `handleViewDocument()`，而这个路径内部才会处理 `previewExpanded`

这意味着在当前主路径下：

- 点击“查看全文”只会切换 `document_display_mode='full'`
- 但不会自动把预览区域展开
- 结果是“全文数据源切换了，界面上却没有任何可见变化”

另外，若 live 阶段 artifact 元数据尚未就绪，则：

- `ensureMessageFinalDocumentContent()` 的 fetch 流程也可能根本没有启动条件
- 用户看到的就是“点击无明显响应”

#### 根因结论

**当前查看全文链路只完成了“切模式”，没有完成“展开完整预览/进入完整展示区”的最后一步。**

## 4. 当前实现完整性评估

### 4.1 已经相对正确的部分

以下部分当前方向是对的，可继续沿用：

1. `long_document_enabled` 作为前端单一显式信号。
2. `planning_outline / outline_role / outline_source / base_outline` 作为长文档规划回放元数据。
3. 历史消息与 generation run 的后端 replay 增强方向。
4. `LongDocumentMessageEnhancements` 抽到独立目录的结构化拆分。
5. artifact 版本链 root 查询能力与 `ListRevisions` 收敛方向。

### 4.2 仍不完整或不准确的部分

当前仍需修正的点：

1. live 规划阶段没有使用“工具步骤组件”展示 synthetic planning/retrieving 过程。
2. 规划面板与 live timeline 没有做一体化布局。
3. artifact 注册完成后没有二次回推到前端。
4. 规划状态在 terminal 阶段没有从 `finalizing` 收口为完成态。
5. 查看全文没有把完整预览打开。

## 5. 推荐修正方案

## 5.1 方案总原则

1. 不再为长文档单独造一套全新页面状态机。
2. 继续复用当前 Agent 展示体系，但把“live 长文档阶段”映射成前端可见的步骤组件。
3. 继续以后端显式信号为准，前端不重新做自然语言意图推断。
4. live 与 refresh 后必须走同一套 `planning_outline / artifact / final_document` 语义。

### 5.2 问题一与问题二的联合修正：让规划阶段真正像工具步骤那样可见

#### 推荐结论

**不要把长文档 synthetic progress 伪装成真实 agent tool_call 写进协议层。**

更合理的做法是：

1. 从 `AgentStreamDisplay.vue` 中抽出一个可复用的“步骤卡片展示组件”或“步骤列表样式层”。
2. 新增长文档专用的 `LongDocumentPlanningTimeline.vue`，消费现有 synthetic thinking/progress metadata。
3. 用这个组件在正文前展示：
   - 检索关键词
   - 检索知识库
   - 规划大纲
   - 当前章节生成进度

#### 原因

如果把长文档内部步骤伪造成真正的 `tool_call/tool_result`：

- 会污染 agent 历史语义；
- 会让 `agent_steps` 混入本不属于真实工具的伪工具调用；
- 后续 replay、导出、调试都更难解释。

相比之下，**保持后端继续发送 synthetic progress，但前端把这些 progress 映射成“工具步骤样式卡片”**，更符合“复用当前组件”且低耦合。

#### 建议改动

1. 提取 `AgentStreamDisplay.vue` 中步骤卡片的公共样式与基础组件。
2. 新增 `frontend/src/views/chat/long-document/components/LongDocumentPlanningTimeline.vue`。
3. 新增一个 long-document progress 解析 composable，例如：
   - `useLongDocumentPlanningTimeline.ts`
4. 解析现有 `thinking` 事件中的以下字段：
   - `stage`
   - `progress_label`
   - `query_current/query_total`
   - `section_current/section_total`
   - `section_title`
   - `planning_outline`
5. 以步骤卡片形式渲染：
   - “搜索关键词”
   - “检索知识库”
   - “规划文档大纲”
   - “生成第 N 章”

#### 验收标准

1. 正文首个 token 出现前，页面已经出现规划步骤区。
2. 检索与规划过程中，用户能看到当前步骤和实时结果摘要。
3. 规划大纲控件与步骤区同时可见，不再只剩 loading dots。

### 5.3 问题三的修正：artifact 注册完成后要自动推回前端

#### 当前根因

当前 live complete 先到，artifact 持久化后到；前端版本卡片只依赖 live complete 的 `chat_document_artifact`。

#### 推荐方案

在 `completeAssistantMessageInPlace` 中，artifact 注册成功后追加一个**长文档元数据补丁事件**到当前 stream：

- 推荐新增 event type：`document_artifact_ready`
- 或在现有协议下新增一个 metadata patch response type

补丁事件内容至少包含：

- `chat_document_artifact`
- `final_document_mode`
- `final_document_artifact_id`
- `long_document_enabled=true`
- `document_generation_status`

#### 为什么不建议依赖前端轮询

前端在 complete 后主动轮询 artifact 虽然可行，但会带来：

- 新的时序竞争；
- 额外接口压力；
- 页面端“为何要等一会儿才出现”的不稳定体验。

更合适的是后端在 artifact 真正注册成功后显式告诉前端。

#### 建议改动点

- `internal/handler/session/qa.go`
  - 在 artifact 注册成功并拿到 `aggregated.Artifact` 后，追加 stream patch
- `internal/handler/session/agent_stream_handler.go`
  - 如需复用现有 complete 合并逻辑，可新增 metadata patch 处理
- `frontend/src/views/chat/index.vue`
  - 收到该补丁后立即 `assignChatDocumentArtifactToMessage()`

#### 验收标准

1. 长文档完成后不刷新页面，版本卡片立即出现。
2. 手动续写/修订完成后也同样立即出现新版本卡片。

### 5.4 问题四的修正：规划状态需要 terminal 收口

#### 当前根因

规划面板当前只看最后一条 progress thinking 的 `stage`，没有把 `agent_complete` 的 terminal 状态用于最终收口。

#### 推荐方案

在 `useLongDocumentPlanning.ts` 中新增一个**派生显示状态**：

- 若消息已 terminal：
  - `document_generation_status=completed` -> `completed`
  - `document_generation_status=needs_review` -> `needs_review`
  - `document_generation_status=blocked` -> `blocked`
- 仅在非 terminal 时才回退使用 `latestProgressEvent.stage`

同时 `LongDocumentOutlinePanel.vue` 的 `stageText` / `stageTheme` 需要新增：

- `completed` -> 已完成
- `needs_review` -> 待复核
- `blocked` -> 已阻断

#### 验收标准

1. 完成后不再停留在“收尾中”。
2. completed/needs_review/blocked 三种终态显示准确。

### 5.5 问题五的修正：查看全文必须真正进入整文显示流程

#### 当前根因

当前“查看全文”只切换 `document_display_mode='full'`，但没有自动展开预览区。

#### 推荐方案

把“切换全文数据源”和“打开完整预览”拆成两步并保证联动：

1. 点击“查看全文”时先执行：
   - `ensureMessageFinalDocumentContent()`
   - 获取 `final_document_content` / `artifact.content_snapshot`
2. 获取成功后：
   - `message.document_display_mode = 'full'`
   - `message.document_preview_expanded = true`
3. `ChatDocumentArtifactCard.vue` 改为：
   - 当进入 full 模式时自动展开预览；
   - 或由父组件显式传入 `previewExpanded` 状态。
4. 如果获取失败：
   - 明确提示“完整文档暂不可用”
   - 但不能只是 silent no-op。

#### 推荐结构

建议把预览展开状态从 `ChatDocumentArtifactCard.vue` 内部局部 `ref` 提升到父层状态，避免：

- card 内部知道 mode 变化，但父层不知道是否展开；
- drawer / card / future full-document modal 无法共享同一显示状态。

#### 验收标准

1. 点击“查看全文”后，完整文档内容立即可见。
2. 点击“查看修改内容”后，再切回 delta 视图。
3. 对章节续写场景，全文展示的是合并后的整文，而不是仅第三章 delta。

## 6. 建议实施顺序

### 第 1 步：先修 live 规划可见性

先完成：

1. `LongDocumentPlanningTimeline.vue`
2. `useLongDocumentPlanningTimeline.ts`
3. 抽取 `AgentStreamDisplay.vue` 中公共步骤卡片样式

原因：

- 这是第 1、2、4 个问题的共同前提。

### 第 2 步：再修 artifact completion 回推

先让版本卡片在完成后立即出现。

原因：

- 第 3、5 个问题都依赖 artifact 与完整快照能在 live 阶段及时到达前端。

### 第 3 步：最后修“查看全文”的展开流程

原因：

- 等 live artifact 回推稳定后，全文查看链路才不会再有额外分支兜底。

## 9. 最终结论
