# 内置智能体推荐问题不显示 — 审查文档

> 审查时间：2026-07（开发环境）
> 现象来源：聊天页面截图 — 顶部下拉框可选「快速问答 / 智能推理 / 维基问答 / 数据分析师」四个内置智能体，输入框上方的**推荐问题区域为空白**（红框区域），无论切换到哪一个内置智能体都不显示。
> 结论先行：**两个独立缺陷叠加**：
> 1. **缺陷 A（权限，主因）**：内置智能体一旦被租户修改过配置，DB 持久化行会以 `visibility='private'` + `created_by=''`（空）落库；推荐问题接口的权限门 `canReadResource` 判定 `private` 资源只允许 `CreatedBy==当前用户`，空 `created_by` ⇒ **所有非平台管理员用户一律 1002 权限拒绝**。
> 2. **缺陷 B（数据，次因）**：即使权限通过（如平台管理员 tenant 10000），当前租户没有任何合格的问题源数据（无 generated_questions 的文本块、无 FAQ 推荐块、无 wiki 页、内置智能体无 SuggestedPrompts 兜底）⇒ 接口成功返回 `questions: null`，前端仍不渲染。

---

## 1. 前端触发链（为什么"静默空白"）

页面为 `frontend/src/components/menu.vue`（IntraMind 品牌对话页），推荐问题逻辑在 `frontend/src/views/chat/index.vue`：

| 环节 | 位置 | 行为 |
|---|---|---|
| 请求守卫 | `fetchSuggestedQuestionsIfNeeded` (L~376-420) | 仅当 `!historyLoading && messagesList.length === 0` 才发起（有新消息立即取消展示） |
| 智能体选择 | `fetchSuggestedQuestions` | 读取 `useSettingsStoreInstance.selectedAgentId`；**无 agentId 直接 return**；请求 `GET /api/v1/agents/:id/suggested-questions?limit=6`（参数来自 `settings.ts` `getSuggestedQuestionsParams`） |
| 失败兜底 | `catch` 分支 | **静默置 `suggestedQuestions = []`**，不弹错、不记日志到 UI |
| 渲染条件 | 模板 L20-47 | `v-if="messagesList.length === 0 && !loading"` 且 `suggestedQuestions.length > 0` 才渲染问题气泡 |

⇒ 后端无论返回 1002 错误还是 `questions: null`，前端表现完全一样：**红框区域空白**。所以必须从后端 API 入手区分。

API 定义：`server` 路由 `internal/handler/router.go:727`（guard 为 `g.Viewer()`，任意登录用户可调），处理函数 `CustomAgentHandler.GetSuggestedQuestions`（`internal/handler/custom_agent.go:743`）。

## 2. 后端请求处理链

```
GET /api/v1/agents/:id/suggested-questions
 └─ handler GetSuggestedQuestions (custom_agent.go:743)
     ├─ h.getReadableAgent(c)               ← 权限门（缺陷 A 卡点）  custom_agent.go:66
     │    └─ visibilityService.CanAccessAgent(userId, tenantID, agentID, canBypass)   agent_visibility.go:89
     │         ├─ canBypass = isPrivilegedResourceOperator(user) = IsSystemAdmin||IsSuperAdmin   (rbac_lookups.go:160 / context_helpers.go:155)
     │         └─ canReadResource({Visibility, OrganizationID, CreatedBy})  same_tenant_scope.go:172
     │              ├─ global → true
     │              ├─ private → CreatedBy != "" && CreatedBy == userID   ← 空 created_by 永远 false
     │              └─ org    → org ∈ 用户可读组织
     └─ service GetSuggestedQuestions (custom_agent.go:501)   （缺陷 B 卡点）
          ① agent.Config.SuggestedPrompts（内置智能体均为空 → 跳过）
          ② KB 作用域 ResolveAgentKnowledgeBasesForCurrentUser（agent_kb_scope.go:23，仅同租户；
             kb_selection_mode=all → 能力过滤 DeriveKBFilterForAgent，RAG 类要求 vector/keyword 索引）
          ③ 三个问题源轮询取数：
             a. FAQ 推荐块  chunks: chunk_type=FAQ & flags&Recommended  （全库 0 条）
             b. 文本块 generated_questions  metadata->'generated_questions' 长度>0 的 TEXT 块
             c. wiki 页（AgentModeQuickAnswer 跳过 wiki 源）
          ④ 无 KB 且无问题 → truncateQuestions(仅 SuggestedPrompts) → questions:null
```

### 2.1 权限门读取的是哪条记录

`customAgentService.GetAgentByID`（`custom_agent.go:126`）：内置智能体**优先查 DB**（加载租户定制配置），DB 命中则用 DB 行（仅名字/描述等本地化元数据覆盖为 YAML 值）；DB 未命中才用 YAML 登记表。

**YAML 工厂构造的智能体（`buildAgentFromEntry`, `builtin_agent_config.go`）不设 Visibility，结构体零值 = `""`；而 GORM 模型字段带 `gorm:"default:'private'"`（`custom_agent.go:94`）——只有写 DB 时才变 `private`。一旦 DB 命中，权限判定读到的就是 DB 行的 `visibility/created_by`。**

### 2.2 缺陷 A 的根因：DB 持久化行的来源

`updateBuiltinAgent`（`custom_agent.go:327`）：用户通过 `PUT /agents/{builtinId}` 修改内置智能体配置时，若 DB 无行则新建：

```go
newAgent := &types.CustomAgent{
    ID: defaultAgent.ID, Name: ..., Description: ..., Avatar: ...,
    IsBuiltin: true, TenantID: tenantID, Config: agent.Config, ...
    // ← 没有 Visibility、没有 CreatedBy
}
s.repo.CreateAgent(ctx, newAgent)   // GORM default:'private' 生效，created_by=''
```

⇒ 内置智能体的持久化行天然是 `visibility='private', created_by=''`，而 `private` 的语义是"仅创建者可见"——**没有创建者的私有资源，对任何非特权用户都不可读**。

DB 实证（`custom_agents` 表）：

| tenant | 8 个内置行 (4 id × 2 租户) | visibility | created_by | 创建时间 |
|---|---|---|---|---|
| 10000 | builtin-quick-answer / smart-reasoning / wiki-researcher / data-analyst | `private` ×4 | `''`(空) ×4 | 2026-04-23 |
| 10005 | 同上 4 id | `private` ×4 | `''`(空) ×4 | 2026-07-15 04:39~04:43（当天短时间内逐个保存过配置） |

即：**两个租户都已触发过"修改内置智能体配置"，两条线都命中缺陷 A**。

### 2.3 为什么下拉框里"看得到"却"查不到"（接口不一致）

`ListAgents`（`agent_visibility.go:60`）**无条件按固定顺序追加全部内置智能体**（"Add built-in agents in order"），可见性过滤只作用于自定义智能体；而 `GetSuggestedQuestions` / `GetAgent`(L282) / `CopyAgent`(L655) 走 `getReadableAgent` 严格可见性校验。⇒ 普通用户在列表里看得到 4 个内置智能体，但任何"按 id 读"的接口（详情、复制、推荐问题）全部 1002。

### 2.4 运行时复现（缺陷 A，决定性证据）

生成带 `auth_tokens` 支撑的 JWT（`/tmp/genjw.go` + 临时插入 token，已在使用后撤销），curl 复现：

```
tenant=10005 (hlsa, is_super_admin=f) ×4 内置智能体:
  {"error":{"code":1002,"message":"Permission denied to access this agent"},"success":false}   ×4
```

与用户截图现象**完全对应**：4 个内置智能体全部无推荐问题，且是权限错误（前端静默吞掉）。

## 3. 缺陷 B：权限通过后仍无数据（tenant 10000）

tenant 10000 平台管理员 `admin`（`is_super_admin=t`，走 bypass 通过权限门），API 实测：

```
tenant=10000 (admin, is_super_admin=t) ×4 内置智能体:
  {"data":{"questions":null},"success":true}   ×4
```

逐层排查 service 的取数逻辑，10000 租户的问题源全部为空：

| 问题源 | 条件 | 10000 现状 | 结果 |
|---|---|---|---|
| ① SuggestedPrompts | 内置智能体 YAML 未配置 | 4 个内置智能体均无 | 0 |
| ② KB 作用域 | 同租户 + 能力过滤（RAG 要求 vector/keyword） | 存活 KB 仅 `__chat_history__`（vector+keyword，9 块，0 generated_questions）与 `北下街数据库测试`（**database 类型，无 vector/keyword → 被能力过滤排除**） | 最多 1 个空 KB |
| ③a FAQ 推荐块 | chunk_type=FAQ & Recommended 位 | 全库 0 条 | 0 |
| ③b 文本块 generated_questions | metadata 数组长度>0 | 10000 无任何一块带该字段（全库 731 条 wiki 页、245 条带 generated_questions 的块**全部属于 tenant 10005**） | 0 |
| ③c wiki 页 | 快速问答模式 `AgentModeQuickAnswer` 直接跳过 wiki 源 | 10000 wiki 页数据虽历史上有但无有效 KB | 0 |

⇒ `questions: null` **在 10000 是"数据面空"而非逻辑错误**，属预期行为的外显。

**对照：tenant 10005 恰恰拥有全部问题数据**（HLSA 产品库 global、vector+keyword+wiki，269 个有效块、245 块带 generated_questions、731 wiki 页），若无缺陷 A 阻塞，本应能出推荐问题。两缺陷叠加后：**10005 有数据但权限死，10000 权限通但无数据**——两个租户都表现为空白。

## 5. 修复方向（先评审，暂不改代码）

### 方案 1（推荐，治缺陷 A 根因）：内置智能体不应用"私有可见性"

内置智能体是平台级资源，语义上应对租户全员可读，不应存在"私有无主"状态。二选一或组合：

- **1a. 判定侧**：`CanAccessAgent` 对 `IsBuiltinAgentID(agentID)` 跳过 `canReadResource`（租户归属已由 `GetAgentByID` 的 `tenantID` 查询保证），仅保留同租户校验。
- **1b. 写入侧**：`updateBuiltinAgent` 新建持久化行时显式 `Visibility: types.KBVisibilityGlobal`；并加一次性数据修复迁移：

  ```sql
  UPDATE custom_agents SET visibility='global'
   WHERE is_builtin AND deleted_at IS NULL AND visibility <> 'global';
  ```

两者结合最稳：**1b 修存量+新增数据，1a 兜底防御**（即使未来再出现未设 visibility 的路径也不会复现"无主私有"）。

### 方案 2（治缺陷 B 体验，可选）：空数据时的兜底

- 前端：`questions` 为空时显示 1~2 条通用引导语（i18n，如"问我任何问题"），或保持空白但避免布局塌缩；
- 后端：为内置智能体在 YAML 增加默认 `suggested_prompts` 兜底（当前 ① 取数链已支持，只是没配）；
- 数据面：复核 `__chat_history__`（纯会话沉淀库）是否应计入推荐问题作用域——建议**剔除**，避免其成为唯一"合格"KB 时拉低取数。

### 不做的事

- 不给 `ListAgents` 的内置智能体补可见性过滤（方向相反，会让普通用户连内置智能体都看不见，与产品预期相悖）。
