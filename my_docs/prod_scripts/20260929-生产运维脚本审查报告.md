# prod_scripts 生产启动脚本审查报告

- **审查日期**: 2026-09-29
- **审查对象**: `my_docs/prod_scripts/` 下 6 个脚本（`compose.sh` 核心 + `start/stop/status/logs/rebuild.sh` 薄封装）+ `README.md`，并交叉核对 `docker-compose.yml`、`Makefile`、`.env`、相关 Dockerfile
- **审查方法**: `bash -n` 静态语法检查、本机实测（Bash 5.3.9 / Docker Compose 2.40.3）、`docker compose config` 校验、与 `make docker-build-*` 构建链路逐项对照

## 总体结论

> **不能直接正常启动。** 核心阻塞点是 **frontend 镜像构建链路不完整**：
> `start.sh` / `rebuild.sh` 默认构建 frontend，但 `compose.sh build` 缺少
> Makefile 中的 `build_frontend_dist.sh` 前置步骤，而 `frontend/Dockerfile`
> 只做 `COPY dist /usr/share/nginx/html`（镜像内不构建）、本机 `frontend/dist`
> 不存在 —— 因此 **首次 `start.sh` 会在 build frontend 阶段必然失败**，
> 导致整个 `up` 无法完成（见 P0-1）。
>
> 其余链路（语法、compose 配置合法性、profile 白名单、project 隔离、
> 健康等待、端口体检、.env 兜底）均验证通过，属可用设计；另有 1 个 P1
> 级配置残留与若干 P2 级问题需修正后才算干净的"生产态"。

**实测依据**:

```
$ for f in compose.sh start.sh ...; do bash -n $f; done   # 全部 OK
$ docker compose config --quiet                            # OK
$ docker compose config --services                         # docreader postgres redis app frontend（与脚本 CORE_SERVICES 一致）
$ build frontend（本机手动实测的等效命令）                # 缺 dist 必败（见 P0-1，本机另受 docker 权限限制，见 P2-5）
```

## P0 — 启动阻断

### P0-1 `compose.sh build frontend` 缺少 `build_frontend_dist.sh` 前置步骤（首次启动必败）

`frontend/Dockerfile` 是**纯拷贝**构建：

```dockerfile
# Requires frontend/dist — run ./scripts/build_frontend_dist.sh before --build
COPY dist /usr/share/nginx/html
```

Makefile 的等价链路有显式前置：

```make
docker-build-frontend:
	./scripts/build_frontend_dist.sh        # ← compose.sh 缺这一步
	docker build ... -f frontend/Dockerfile -t wechatopenai/weknora-ui:latest frontend/
```

而 `compose.sh` 的 `cmd_build` / `cmd_rebuild_all` 只执行
`docker compose build --pull=false frontend`，`frontend/dist` 不存在时
BuildKit 报 `COPY failed: file not found`。本机实测 `frontend/dist` 不存在、
且被 `frontend/.gitignore` 忽略，**全新克隆或清理后 `start.sh` 必然在此失败**；
`rebuild.sh`（发版主路径）同样命中。

**影响**: `start.sh`（默认 build 三镜像）→ frontend build 失败 →
`set -euo pipefail` 使脚本中止，核心五服务无法 up。已构建过 dist 的旧机器
不受影响，故该缺陷呈"换机/换人复现"的特征。

**修复建议**（`compose.sh`，`cmd_build` 的 frontend 分支与 `cmd_rebuild_all` 前）:

```bash
frontend) "${DC[@]}" build --pull=false frontend ;;
```
改为：
```bash
frontend) "${REPO_ROOT}/scripts/build_frontend_dist.sh" && "${DC[@]}" build --pull=false frontend ;;
```
并在 `cmd_rebuild_all` 的 targets 含 frontend 时先跑一次 dist 构建。
（或最低限度：README「快速上手」补一行"先 `./scripts/build_frontend_dist.sh`"。）

### P0-2 本机当前用户无 docker 权限，任何脚本第一条命令就会 die

审查时本机实测：`docker compose build` 报
`permission denied ... /var/run/docker.sock`，`lenovo` 不在 `docker` 组。
`start.sh` 会停在 `check_docker`（`docker info` 失败）→ die。

**修复**: `sudo usermod -aG docker $USER` 后重新登录，或改用 `sudo` 运行脚本。
（这是环境问题而非脚本 bug，但会在"验收脚本能否启动"时第一个撞出，故列 P0。）

## P1 — 功能/配置错误，不阻断但影响正确性

### P1-3 `.env` 的 `DB_NAME` 残留 dev 库名 `weknora_mdev`（✅ 已修正）

`docker-compose.yml` 中 `POSTGRES_DB=${DB_NAME}` 无默认值，审查时
`.env` 为 `DB_NAME=weknora_mdev` —— 生产卷（`weknora-prod_postgres-data`）
首次初始化时会落库名 `weknora_mdev`，与"生产环境"语义、与文档宣传的
"生产/ dev 天然分离"都不符。

**修正结果（2026-09-29 同日）**：`.env` 已切为生产值 `DB_HOST=postgres` /
`DB_NAME=weknora_prod`；新建 `.env.local` 覆盖回 `DB_HOST=localhost` /
`DB_NAME=weknora_mdev` 供本地 dev-app（`scripts/dev.sh` 后 source `.env.local`），
dev 数据不受影响（旧卷已初始化）。详见文末"修正实施记录"表 #3。

### P1-4 `start.sh` 的 `--build` 语义与文档/注释不符

`compose.sh cmd_up` 对 `--build` 的注释写"本地无镜像才构建"，`start.sh`
头注释也是"本地缺镜像才构建" —— **实际 `docker compose up -d --build`
每次都会强制 rebuild 三个镜像**（compose v2 语义），且 `start.sh --no-build`
虽然能解析，但"默认 --build + 透传用户参数"导致无法通过 `start.sh` 关闭
（用户传 `--no-build` 变成 `up --build --no-build`，`--build` 仍生效，
build=true 已先固化）。结果：每次"启动"都全量重构建（Go 编译数分钟），
"幂等启动"与"发版"的语义混同。

**修复建议**: `start.sh` 默认不透传 `--build`（缺镜像时 compose 会自动按
`build:` 定义自构，README 已注明此行为），`--build` 由用户显式传；
`compose.sh` 同步修正注释。

### P1-5 compose 构建缺少 Makefile 的版本注入与 Go 代理参数（文档失实）

`compose.sh cmd_build` 注释声称"版本信息自动从 git 注入"，**实际不成立**：
`docker compose build` 不会执行 Makefile，`Dockerfile.app` 的
`VERSION_ARG/COMMIT_ID_ARG/BUILD_TIME_ARG/GO_VERSION_ARG`、`GOPROXY_ARG`、
`GOPRIVATE_ARG` 全部拿不到（默认空）。后果：
- app 镜像内版本/commit/构建时间均为空，排障时无法对版本；
- Go 依赖走 `GOPROXY` 默认值（国内网络下 `go mod download` 极易慢/失败），
  而 Makefile 路径通过 `get_version.sh` + 代理参数规避了这一点；
- `docker compose build app` 的镜像 tag 是 `weknora-app:latest`
  （`WEKNORA_VERSION` 未设）；与 Makefile 产物 tag 相同，本地缓存会互相覆盖——
  这本身是设计意图（复用 tag），但"版本信息注入"的表述需从文档里删掉。

**修复建议**: `cmd_build` 的 app 目标改为与 Makefile 对齐：
```bash
eval $(./scripts/get_version.sh env)
"${DC[@]}" build --pull=false \
  --build-arg VERSION_ARG="$VERSION" --build-arg COMMIT_ID_ARG="$COMMIT_ID" \
  --build-arg BUILD_TIME_ARG="$BUILD_TIME" --build-arg GO_VERSION_ARG="$GO_VERSION" \
  app
```
GOPROXY 同理透传；或文档明示"建议先 `make docker-build-all`，compose build 仅轻量重建"。

### P1-6 生产 `FRONTEND_PORT=80` 需要 root/特权

当前 `.env` `FRONTEND_PORT=80`。Docker 本身不受 CAP_NET_BIND_SERVICE 限制，
容器内绑 80 没问题；但若本机 nginx 等以 root 占 80，`check_host_ports`
会告警（已验证逻辑正确）。建议生产验收机显式把 `FRONTEND_PORT` 改为
非特权端口（如 8083），把 80 交给前置反代——这属于部署规范，非脚本缺陷，
README 已有提示，此处仅记录现状。

## P2 — 建议改善（不阻断）

1. **`check_dev_conflict` 覆盖面不足**：只探测 `WeKnora-postgres-dev` /
   `WeKnora-redis-dev` 两个容器名。dev 栈的 `WeKnora-app-dev`（Makefile dev
   链路起同名 app，镜像内同样占宿主 8081/80 映射，见 `APP_PORT=8081`
   已被占用场景）、`WeKnora-frontend-dev` 等不在检测内。建议改为
   `grep -cE 'WeKnora-(app|frontend|docreader|postgres|redis)-dev'` 或直接
   `docker compose -f docker-compose.dev.yml ps --running`。另外
   `grep` 容器名清单时注意 `WeKnora-odl-hybrid`（dev compose 里该容器名
   无 -dev 后缀）与生产 profile 同名会互相干扰，命名宜统一加 -dev。
2. **`cmd_down` 的 `--purge-data` 是 `down` + 再 `down -v` 两步**：结果正确
   但第二次 `down -v` 作用域仍是 `COMPOSE_PROJECT_NAME=weknora-prod`，
   无误删风险（README 的"下卷只删生产卷"结论成立）；可简化为一次
   `down -v`。注意它**不会**清理 `--purge` 之外的残留容器（已 remove），
   行为符合预期。
3. **`cmd_logs` 裸服务名切换默认集靠 `${#svcs[@]} -eq 3` 判断**：若未来
   默认集改动需同步，宜改成显式 `explicit_svcs` 模式（`cmd_up` 已有同款写法）。
4. **`rebuild.sh --profile minio` 先 profile-up 再 rebuild-all**：minio 等
   基础设施 rebuild 语义下无意义（rebuild-all 只认 app/docreader/frontend），
   当前实现"起 minio 容器 + 重建三镜像"可接受，但帮助文本应说明该组合
   的实际效果，避免误解。
5. **`wait_healthy` 对 `status` 为空时（容器尚未出现）会静默重试直到超时**：
   建议 `[[ -z "$status" ]` 时区分"容器不存在"（die，多半 up 失败了）与
   "starting"，缩短误报窗口。
6. **`check_host_ports` 读 .env 用 `grep -E '^KEY='`**：.env 允许
   `export`/引号/行内注释等写法时会漏读而退回默认值——当前脚本生成的
   .env 格式是纯 `K=V`，风险低，可忽略或改 `grep -E '^(export )?KEY='`。
7. **`.env` 缺失时 `check_env_file` 静默复制 `.env.example`**：`.env.example`
   默认值（如 `DB_PASSWORD` 默认空、`REDIS_PASSWORD` 空）会让
   redis requirepass 为空跑起来、postgres 匿名可连——脚本已有 warn，
   建议对生产入口 `start.sh` 升级为 **die 并要求显式确认**（`--accept-defaults`），
   防新人误上线。
