## 第 3 页：企业痛点

**页面标题**

企业知识管理的典型痛点

**页面核心结论**

企业真正缺的不是“更多文档”，而是“让知识被快速找到、准确理解并持续更新”的能力。

**页面主文案**

建议做成 5 个痛点卡片：

1. 知识分散
   文档散落在飞书、Notion、语雀、网盘、邮件和本地文件夹，知识位置不统一。
2. 检索低效
   传统关键词搜索命中率低，员工经常还要继续翻文档、问同事、查历史聊天记录。
3. 知识维护成本高
   文档一多就没人愿意整理，知识库很快过期，Wiki 经常建了但没人维护。
4. 复杂问题难以回答
   很多问题不是“查一篇文档”能解决，而是需要跨资料比对、拆解步骤、调用工具和联网核验。
5. 企业级落地门槛高
   权限、安全、审计、部署、模型选型、数据不出域等要求，决定了普通 Demo 很难进入生产环境。

**讲解词**

大多数企业其实并不缺内容，而是缺少把内容转化为组织能力的机制。传统文档系统解决的是“存放”，搜索系统解决的是“检索”，但都没有解决“理解、回答、推理、沉淀和治理”的全链路问题。IntraMind 正是针对这一点设计的。

- 建议用“痛点图谱”或五卡片版式

什么是 IntraMind 企业内脑

**页面标题**

三种模式，覆盖从简单到复杂的知识场景

**页面核心结论**

同一套平台同时覆盖“快速查答案”“复杂任务推理”“知识自动沉淀”三类场景。

**页面主文案**

| 模式 | 解决什么问题 | 用户价值 |
|------|--------------|----------|

**页面标题**

从知识接入到分发治理的完整能力闭环

**页面核心结论**

IntraMind 覆盖知识生命周期的全链路，而不是单点问答能力。

**页面主文案**

建议做成五层能力地图：

1. 知识接入层

2. 知识理解层
   文档解析、OCR、表格抽取、图片理解、语音转写、智能分块、问题预生成

## 第 8 页：智能推理

**页面标题**

智能推理：复杂问题不只回答，还会自动拆解任务

**页面核心结论**

当问题需要跨文档、多步骤、工具协同或联网核实时，IntraMind 会以 ReAct 智能体方式逐步完成任务。

**页面主文案**

建议做成“流程 + 能力”版式。

流程文案：

提出复杂问题 → 智能体分析任务 → 多轮检索相关知识 → 调用工具或联网搜索 → 综合证据 → 输出结论与依据

能力文案：

- 支持 ReAct 多步推理
- 自动决定是否继续检索、是否调用工具、是否联网
- 可调用知识检索、Wiki 工具、网页抓取、数据分析、MCP 外部工具
- 支持展示思考过程、工具调用过程和引用来源
- 可配置自定义 Agent，限定知识边界、模型、提示词、工具权限

可加一个典型例子：

“对比三份合同的付款条款，并参考行业惯例给出风险提示。”

**讲解词**

很多企业问题的难点，不在于模型会不会说话，而在于问题本身需要多轮处理。比如合同对比、方案调研、合规检查，单轮检索通常不够。IntraMind 的智能推理模式让系统以智能体方式工作，先拆解，再行动，再总结，最终输出的不是泛泛而谈的答案，而是带有证据链的结论。

## 第 9 页：自动 Wiki 与知识图谱

**页面标题**

自动 Wiki：让知识库自己长出来

**页面核心结论**

IntraMind 不只回答问题，还能把原始文档自动整理成可浏览、可编辑、可演进的知识体系。

**页面主文案**

建议用“Wiki + 图谱”双栏表达。

Wiki 侧：

- 从原始文档自动抽取人物、组织、产品、概念等条目
- 自动生成带出处的 Markdown 页面
- 页面之间自动建立链接，形成知识网络
- 支持浏览器内直接编辑、版本快照、行级 diff、一键回滚

图谱侧：

- 抽取实体与关系，构建知识图谱
- 图谱可视化浏览，支持节点跳转页面
- 问答时可引入 GraphRAG 增强关系型问题的检索效果

可加一句总结：

Wiki 解决“知识整理”，图谱解决“关系理解”，两者一起把知识从文档堆升级为知识网络。

**讲解词**

很多企业不是没有知识，而是没有人有时间把知识整理成体系。自动 Wiki 的价值，是让系统代替人工完成第一轮结构化整理。管理员只需要对关键页面做修订和校正，就能逐步形成企业自己的知识百科。再配合知识图谱，系统就不仅知道“有哪些内容”，还知道“这些内容之间是什么关系”。

## 第 10 页：知识接入能力

**页面标题**

多来源、多格式、可持续同步的知识接入

**页面核心结论**

IntraMind 的第一道门槛不是问答，而是高质量接入知识；这一点它做得足够完整。

## 第 11 页：文档理解与智能分块

**页面标题**

独立文档解析服务，让文档真正“可理解”

**页面核心结论**

IntraMind 的问答质量，建立在对文档结构、图片、表格和音频的系统性理解之上。

**页面主文案**

建议以“能力列表 + 价值说明”方式表达。

能力项：

- 独立 docreader 解析服务，负责文档结构化处理
- 版式分析、OCR、表格抽取、网页正文提取
- 图片理解能力，支持视觉模型解析截图与扫描件
- 音频转写能力，支持语音资料入库
- 分块策略支持自适应、按标题、启发式、递归切分
- 可开启父子分块，提高长文档命中与回答上下文完整性
- 可为分块预生成问题，提升口语化提问召回率

价值说明：

- 文档不是简单切段，而是尽可能保留语义结构
- 核心文档出错时可重新解析或局部编辑，无需反复重传

**讲解词**

做企业知识库，最容易低估的环节就是文档理解。很多系统看起来也支持 PDF、Word，但实际上只是把内容粗暴切开，导致后续检索和回答效果不稳定。IntraMind 在这层投入比较完整，从解析服务、智能分块，到 OCR、VLM、ASR，都在为后面的检索和问答质量打基础。

## 第 18 页：安全与合规

**页面标题**

从凭据保护到私有化部署的全链路安全能力

**页面核心结论**

IntraMind 的安全设计覆盖数据、凭据、网络访问、执行环境和部署边界，符合企业级使用要求。

**页面主文案**

建议用 6 张安全卡片表达：

1. 凭据静态加密
   API Key、MCP 凭据、数据源密码等敏感信息以 AES-256-GCM 加密存储
2. 服务间加密通信
   app 与 docreader 之间支持 gRPC TLS + Token，Redis 可启用 TLS
3. SSRF 防护
   所有外部抓取、URL 导入和回调都经安全客户端过滤，禁止危险内网访问
4. 响应脱敏
   接口不回显敏感字段，只展示是否已配置
5. 技能沙箱
   Agent Skills 在隔离容器中执行，与主系统隔离
6. 私有化与准入控制
   支持本地、私有云、离线部署；可配置邀请制注册和 OIDC 单点登录

可补一句总结：

数据不出域、能力可控、操作可审计，是企业内脑上线的底线要求。

**讲解词**

企业最关心的不是一个 Demo 能否跑起来，而是上线后是否可控。IntraMind 在设计上尽量避免把安全能力留给后续补丁，而是在凭据、网络、运行时和部署模式上都做了前置考虑。对于希望将知识系统用于内部制度、客户资料、研发文档和业务流程的企业，这些能力是决定性因素。

企业内脑最适合采用“小步快跑、分阶段见效”的落地方式。

**页面主文案**

建议用四阶段路线图：

阶段一：PoC 验证

- 选一个高价值知识场景
- 接入 1 至 2 个核心知识库
- 跑通“上传文档 → 问答 → 引用 → 调优”的闭环

阶段二：知识扩容

- 接入 FAQ、飞书/Notion/语雀/RSS 等数据源
- 打通文档结构、标签、文件夹树和分块维护流程

阶段三：能力升级

- 开启 Rerank、智能推理、自动 Wiki、知识图谱
- 针对关键业务场景定制 Agent 和提示词

阶段四：组织级推广

- 接入 IM、网站嵌入、API 或 MCP
- 建立角色权限、审计和运维巡检机制
- 逐步沉淀为跨部门共享知识底座

**讲解词**

知识类系统最忌讳“大而全一次到位”。建议先找一个真实的高频场景切入，例如制度查询、客服资料问答、产品文档检索，验证回答质量和使用习惯。等使用闭环稳定后，再逐步扩展数据源、Agent、渠道和治理能力，这样 ROI 更清晰，组织接受度也更高。

**配图建议**

- 使用四阶段路线图或时间轴
- 可加入“试点部门 → 扩展部门 → 平台化”箭头

## 第 25 页：业务价值总结

**页面标题**

最终价值：让知识真正变成组织生产力

**页面核心结论**

IntraMind 的最终价值，不是多一个系统，而是让企业知识从静态内容变成可复用、可放大、可治理的能力资产。

**页面主文案**

建议从五个价值点表达：

1. 提升效率
   知识获取从“翻资料、问同事”转向“直接提问”，把获取成本从分钟级降到秒级
2. 保留经验
   把隐性经验和散落文档沉淀为可查询、可传承的组织知识
3. 降低维护成本
   借助自动 Wiki、分块编辑和数据源同步，让知识库持续更新而不是越用越旧
4. 增强治理能力
   通过权限、审计、安全和私有化部署，满足企业实际管理要求
5. 形成平台复用
   同一套知识底座可服务多个部门、多个入口和多个 AI 工作流

收束文案：

> IntraMind 企业内脑 = 智能问答 + 智能推理 + 自动 Wiki，让企业知识“能回答、能推理、能自生长”。

**讲解词**

领导层最关心的不是某一个功能做得多先进，而是这套系统能否真正改变组织的知识流动方式。IntraMind 的价值，在于把知识资产从“沉睡内容”升级成“可随时调用的生产力”。对员工是提效，对管理层是沉淀，对 IT 是可治理，对整个组织则是能力复用。

**配图建议**

- 五张价值卡片
- 如果需要更强视觉冲击，可中间放一句主标语，四周环绕价值点
